# 多模态标注平台集成（Label Studio）技术方案

**日期：** 2026-09-28
**状态：** `deferred`（2026-09-28 决策评审：D1 暂缓）。本方案为已归档的决策输入；§10 记录了重新立项时直接可用的 D1–D8 结论。重新立项需用户明确指示，不得自行启动。
**范围（若获批）：** 以深度集成模式引入 Label Studio 作为**多模态标注引擎**（图像/文本/音视频），平台保留全部业务合同；含身份网关、任务导出、schema 翻译、结果回流、部署与安全六个集成面
**不包含：** 表格标注迁移（自研门户保持现状）、iframe 内嵌（历史安全决策排除）、训练数据自动回流（保持人工回传/验收）、CVAT（选定 LS 后不再评估）

## 1. 背景与问题

1. **已交付的自研标注体系**只覆盖结构化表格：通用标注任务、冻结标签 schema、指派、独立标注员门户（8443 三层链路）、回传批次、验收/退回、管理员评审、AutoML 自动标注回注。它与项目权限、审计、数据版本深度耦合，**本方案不迁移它**。
2. **多模态标注（图像/文本/音视频）没有能力**：2026-08-18 决策将 Label Studio 延后；历次计划均写明"未经批准不部署、不做 iframe 和任务同步"。
3. 本方案把该延后事项重新提出为**独立立项**：以深度集成模式引入 Label Studio（Apache-2.0），回答"外部标注引擎如何长在平台合同里"。

## 2. 集成模式对比与推荐

| 模式 | 形态 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A 联邦同步 | 独立部署 LS，任务文件人工导入、结果手工导回 | 起步快、零合同改动 | 审计/项目隔离/幂等全部失守，标注员双账号 | 不推荐 |
| **B 深度集成** | **平台是唯一业务真相源；LS 作为多模态标注前端引擎，双向同步合同化** | 保留全部权限/审计/回传合同；标注员单点登录 | 集成面工作量 ≈ 一个周级项目；新增有状态服务运维 | **推荐（若立项）** |
| C iframe 内嵌 | 平台页面内嵌 LS 界面 | 入口统一 | 被历史安全决策明确排除（会话/token 跨域、点击劫持、越权面） | 排除 |

CVAT 不再单独评估：模态覆盖窄（CV 专用）、基础设施更重；选定 LS 后不并存。

## 3. 总体架构

~~~text
标注员浏览器
   │ 平台登录态（复用门户网关模式：portal session → service token；不做 iframe）
   ▼
平台 API ──鉴权/审计/项目隔离──▶ Label Studio（独立部署，仅内网可达）
   │                                     ▲
   │ ①任务导出：DatasetVersion 样本快照    │ ③结果回流：LS 标注结果 →
   │   + LabelSchema → LS 项目/任务/config │   AnnotationReturnBatch →
   │   （schema 版本 ↔ config 版本绑定）   │   现有回传/验收状态机
   ▼                                     │
MinIO 存储 ◀─────②样本文件经 StorageBinding / presigned URL──────────┘
~~~

核心原则：**LS 内不存在任何平台合同之外的业务状态**——LS 中的标注进度只是过程态，任务发布、指派、回传、验收、导出的裁决权全部在平台。

## 4. 集成面合同

### 4.1 身份与网关

- LS 不直接对外暴露；浏览器一律经平台网关（复用 `ml-platform/annotator/backend` 的门户模式：网关校验 portal session → 铸造短时 service token → LS/平台内部 API）。
- LS 账号由平台 **provisioning**：平台标注员主体（`AnnotatorSubjectMapping`）↔ LS user 1:1 映射表；平台不下发密码原文，LS API token 只存服务端（引用式，Week 13 凭据合同同构）。
- 管理员评审链路不变：管理员在平台侧看批次/样本明细，LS 仅是产生标注的过程工具。

### 4.2 任务导出合同（平台 → LS）

- 导出单元 = 一次指派（assignment）的一个不可变样本集合（DatasetVersion 快照 + scope），LS project ↔ 平台 project 1:1 绑定（映射表）。
- 幂等：导出批携 `export_id`，重放返回既有 LS 任务集，不产生重复任务；每批有界（默认 ≤5,000 任务，可配）。
- 样本文件经 MinIO presigned URL（短期）或 Week 16 StorageBinding 挂载引用，平台不复制数据文件。

### 4.3 schema 翻译合同

- `LabelSchema`（原生版本化：`project_id+name+version` 唯一）+ `LabelColumn`（`machine_key/display_name/value_type/enum_values/min/max/required`）→ 平台侧生成器输出 LS labeling config（XML），**config 内容按 schema 版本存档（不可变），LS 端关闭 config 编辑权限**。
- 已核实：`LabelSchema.version` 与 `LabelColumn.value_type/enum_values` 字段原生存在，翻译锚点无需改模型。int→number、enum→choices、string→text 的映射规则由生成器唯一裁决；平台校验器（NFKC、类型、min/max）在**回流侧**重新执行，不信任 LS 内部校验。

### 4.4 结果回流合同（LS → 平台）

- 已核实：`AnnotationReturnBatch` 以 `assignment_id` 为作用域（`task_revision`/`scope_hash`/`idempotency_key` 唯一）——**LS 回流必须落到指派上**，因此 4.1 的身份映射是硬前提，不是可选项。
- 回流 = LS 完成事件（webhook 或平台轮询）→ 按标注员主体聚合其在该指派下完成的样本 → 创建/追加 `AnnotationReturnBatch`（幂等键 = export_id + LS completion 版本）→ 走**现有**验收/退回状态机。
- **保持人工回传语义**：LS 内"完成"不自动等于"回传"，标注员回到平台门户点回传（与现有表格流一致）；退回修改走平台状态机，LS 侧任务重开由平台指令驱动。
- 不做训练数据自动回流；自动标注（AutoML 回注）仍走平台自有链路，不经 LS。

### 4.5 部署合同

- 组件：LS（Django）+ 独立 PostgreSQL 数据库（复用 compose 的 PostgreSQL 实例、独立 database）+ Redis（复用）；镜像以 digest 固定并进 Week 15 镜像目录（Trivy 扫描联动）。
- 形态跟随 Week 13–15 决策：K8s（namespace + 资源配额走 Week 16）或 compose 服务，二选一在决策门确认；备份/恢复扩展进 Week 11 证据链（LS 库纳入 backup/restore）。
- 升级策略：LS 版本由平台锁定（digest），升级属变更操作，走验收。

### 4.6 安全与审计合同

- 网关隐藏式 404、CSRF、会话规则与现有门户一致；LS 自身认证禁用公网入口。
- LS 关键动作（任务创建/标注提交/项目变更）由平台同步器镜像为平台审计事件（最小集：actor、action、resource、时间）；平台侧错误消息脱敏规则不变。
- LS 内不出现在平台权限模型之外的可见性：LS project 级权限按映射的标注员主体收敛。

## 5. 平台侧新增数据模型（合同级）

| 表 | 作用 |
|---|---|
| `label_studio_bindings` | 平台 project ↔ LS project 映射、LS 实例/凭据引用（env:/file:）、config 版本档案 |
| `annotation_sync_exports` | 导出批：assignment/dataset_version/scope_hash/LS 任务集 id/幂等键/状态 |
| `annotation_sync_returns` | 回流记录：LS completion ↔ 样本 ↔ return batch 映射，幂等、冲突标记 |

迁移在获批后创建（以实现日空闲修订号为准）；不改动既有 `labeling.py` 任何表。

## 6. 接口边界（获批后实现）

平台侧前缀 `/api/annotation-sync`（管理 = `resource.create/update`，查看 = `project.read`；同步执行由服务端调度）：

| 方法 路径 | 语义 |
|---|---|
| POST/GET `/bindings` | 项目 ↔ LS 绑定登记（凭据只存引用） |
| POST `/exports` | 触发一次导出批（Idempotency-Key；返回 export_id 与任务计数） |
| GET `/exports/{id}` | 导出批状态（LS 侧任务数、完成数、失败明细） |
| POST `/returns/sync` | 手动触发回流对账（幂等；正常由轮询驱动） |
| GET `/health` | LS 实例连通性（复用 Week 13 连通性检查合同） |

标注员门户新增"多模态任务"入口：任务列表按 `modality` 标识路由——表格任务进现有工作台，多模态任务经网关跳转 LS 界面。

## 7. 前端交互

- 主平台任务列表：多模态任务显示模态徽标与"去标注"动作（网关跳转）。
- 标注员门户：多模态区块（绑定项目的任务卡、LS 跳转、回到平台回传）。
- 管理页：绑定/导出批/回流状态（含失败明细与手动对账按钮）。
- i18n 与错误码：`SYNC_*` 系列（导出失败、回流冲突、LS 不可达等），中英双语。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 状态真相分裂（LS 过程态 vs 平台业务态） | 回流唯一入口 = 现有回传状态机；LS 完成 ≠ 回传；对账任务幂等 |
| 双 UI 割裂（表格/多模态两套界面） | 任务列表按模态路由；交互规范统一（门户样式令牌）；决策门明确"表格不迁移" |
| 有状态服务运维（升级/备份/监控） | 版本锁 digest；备份纳入既有证据链；LS 不可达降级为显式失败不阻塞平台 |
| 同步风暴/大导出 | 导出批有界 + 幂等 + 队列化（复用 Celery） |
| 许可与合规 | Apache-2.0 社区版；不使用 LS 专有云特性 |

## 12. 方案结论

Label Studio 深度集成的本质是"**买一块标注 UI，长在平台合同上**"：业务真相、权限、审计、回传验收全部留在平台，LS 只做多模态标注体验。D1–D8 结论已收口（§10）；用户重新立项后，它是一个边界清晰、可验收的独立项目。
