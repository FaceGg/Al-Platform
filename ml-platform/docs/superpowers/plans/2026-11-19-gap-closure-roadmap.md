# 补齐路线实施计划

- **日期**：2026-11-19
- **依据**：[补齐路线实施文档](../../补齐路线实施文档.md)（四段门控路线，41 项 + 诚实设计 5 项；功能细节、实现要点、单模块验收口径一律以该文档为准，本计划不重复）
- **定位**：把路线文档转成**批次内阶段顺序、依赖关系、验收节奏与横向工程合同**的执行视图。本计划回答「按什么顺序做、每步交什么、怎么算过」，不回答「每个功能长什么样」。
- **与主线关系**：AutoML Agent 智能体计划（2026-10-22）仍为当前主要开发入口；本路线第一批可与其收尾工作并行，带宽冲突时**主线优先**。第三、四批为门控批次，未过门不得启动。

## 2. 第一批实施排期（13 项 · 5 阶段）

> 排序依据路线文档「模块间依赖主线」：数据侧（B1-08）、事件侧（B1-07→05→01→02）、模型侧（B1-09）、治理侧贯穿。F1 三线互相独立可并行；F3 三项**共用同一聚合视图**，必须同阶段做以保证 KPI 与列表口径严格一致（竞品趋势页与日报数字打架是反面教材）。

### F1 · 基座（B1-10 场景与设备管理 / B1-08 外部库直连 / B1-11 通知渠道）

- **为什么先做**：B1-10 的字段角色与设备台账被 B1-02（波形列把关）、B1-05（心跳/离线）、B1-07（场景 schema）引用；B1-11 是 B1-01 SLA 通知与漂移严重级推送的通道底座；B1-08 是数据侧源头。
- **交付物**：三张新表族（场景配置/设备台账含心跳、数据源连接（Fernet 加密）、通知渠道扩展）+ 各自 API + 前端管理页 + 迁移。
- **阶段验收**：新场景→字段角色→训练特征排除全链；设备注册→心跳→离线状态；白名单外 SQL 拒绝落审计；三新通道测试消息可达且 secret 不回显。
- **B1-10 同时预留**：设备影子 desired/reported 状态字段（诚实设计⑤）。

### F2 · 预警处置主干（B1-01 预警中心 → B1-02 处置工作台 → B1-12 证据链导出）

- **顺序硬依赖**：B1-02 从 B1-01 点入；B1-12 打包 B1-01/02 产生的轨迹与判据。
- **交付物**：alerts 表 + alert_events 轨迹表 + 误报回流标注队列挂接（复用 annotation_strategies）+ 判据优先级引擎（规格超限→3σ→2σ→基线偏离 30%，竞品口径可复算）+ MinIO 附件 + ZIP/MANIFEST.SHA256 导出 + 预警中心与处置工作台前端页。
- **阶段验收**：路线文档 B1-01/02/12 三节验收口径逐条过；**确认动作强制责任人**（防呆优于竞品）；异机解包 SHA-256 校验通过。
- **通知联动**：SLA 临期/超时接 F1 通知中心。

### F3 · 监控驾驶（B1-03 驾驶舱 / B1-04 趋势帕累托 / B1-05 实时监控）

- **同阶段强约束**：三页共用**同一 SQL 聚合视图**（alerts + 推理结果），单测锁「KPI 数字 = 下钻列表数字 = 趋势页计数」；NG 词表配置与后续 B3-08 质量报告共用一份。
- **交付物**：聚合视图 + 四级范围（工厂→车间→产线→场景）联动切换 + SSE/WebSocket 推送（复用闭环事件流，5 秒上屏）+ 设备三级树（读 F1 台账）+ 陈旧数据横幅（距最后推理 >24h）。
- **阶段验收**：模拟事件 5 秒内上屏；口径一致性单测；四级切换全卡联动；设备离线状态准确反映心跳。

### F4 · 统计与漂移（B1-06 SPC / B1-09 漂移页）

- **两项独立可并行**；均不含对 F2/F3 的硬依赖，但漂移报告的「一键转重训提案」在第一批只做到提案生成（审批流在第二批 S1）。
- **交付物**：SPC 纯函数统计库（Nelson 1–8 判异 + Cp/Cpk/Pp/Ppk/Cpm/Cr/σ/PPM 全套，8 类判异单测全覆盖）+ 控制图/直方图前端；drift_reports 表族 + PSI 从闭环事件流**抽出独立化**（不重写算法，重组报告与页面——注意不破坏现有 PSI 内嵌触发重训链路）+ 定时批检 beat 任务 + 口径脚注（诚实设计②）。
- **阶段验收**：竞品同口径数据复算一致（106,504 行取最新 5,000、5 样本/组用例作为回归）；缺规格限能力指数留空不报错；定时批检真实产出分级报告且严重级推送通知。

### F5 · 接入开放（B1-07 Kafka / B1-13 QMS/MES 只读接口）

- **B1-07 依赖 F1 的场景 schema 声明**；compose 可选 profile 不加重默认栈；按业务样本 ID 幂等去重；全站页脚实时链路状态（诚实设计⑤变体）。
- **B1-13 相对独立**：platform_api 反向改造为业务数据只读开放（九类 GET 资源、API Key 掩码+轮换宽限期、单页 500 上限）。
- **阶段验收**：端到端延迟秒级、重放不重复计数；外部脚本持 Key 分页拉取、轮换后旧 Key 401、写动词全 405。
- **M1 收口**：第一批真实数据端到端演练（建议用三端标注运营的真实流量触发一条预警走到关闭），验收证据 `验收-补齐路线-M1.md/json`，六 job CI 绿。

## 3. 第二批实施排期（14 项 · 5 阶段）

> 启动门控：第一批 M1 达成。治理四件套（B2-G1~G4）全部来自工序平台已演练机制，照抄不改语义。

### S0 · 前置核查（B2-T）——已收口，无需立项

- **结论**：无监督异常检测建模出口**已存在**，B2-T 关闭，第二批仍为 14 项，不增项。代码证据（2026-11-19 内容级复核）：`backend/app/services/automl_anomaly.py`（IsolationForest/OneClassSVM 统一分数口径）+ `automl_anomaly_ae.py`（AutoEncoder），2026-11-12/13 全量方案已交付，按族混合形态。
- 路线文档 B2-T 提到的「异常排名稳定度作为无标签搜索比较准则」**同样已有实现**：`automl_anomaly.py` 的 `stability_check`、`rank_candidates`（stability 为第三排序键）、冠军资格门禁（含 stability 指标）三处。无残留核查项。

### S1 · 审批与审计底座（B2-07 统一四眼审批中心含 B2-10 / B2-08 动作审计）

- **为什么先做**：B2-03 门禁、G2 预授权、重训提案、配方变更全部汇入审批队列；B2-08 贯穿本批所有 LLM/Agent 调用。
- **交付物**：AgentTask 审批流泛化为统一队列（类型字段 + 有效期默认 72h + 过期自动回收 + 过期前 12h 提醒）；发起人≠审批人强制、拒绝必附意见、批准后平台执行回写留痕；动作审计表（请求/结果/权限/耗时/审批关联/追踪 ID）+ 键名脱敏规则（password/secret/token/webhook/authorization/cookie/apiKey → \*\*\*）+ CSV 导出。
- **阶段验收**：审批人=发起人被拒；72h 过期自动回收实测；脱敏规则单测；此后本批每次 LLM 调用自动入审计。

### S2 · 发布治理链（B2-G1 → B2-09 → B2-02 → B2-03 → B2-G2 → B2-G3）

- **链式顺序即依赖**：盲测锁定（G1）→ Champion/Challenger 别名路由（B2-09）→ 影子推理对照（B2-02，Challenger 即影子候选）→ 发布门禁（B2-03，终验指标**只能取自 G1 锁定盲测**——直接堵竞品「F1 0.999 浅验证集放行」漏洞）→ 预授权层（B2-G2，授权检查中间件）→ 影子窗口+灰度+工位回执（B2-G3，rollout 金丝雀映射灰度段）。
- **交付物**：划分锁定 + 盲测台账（已用样本进历史证据，新轮次必须新批次）；release_checks 表随发布单归档；preauthorizations 表（工位/验收标准版本/有效期/次数余额）；三段式发布状态机；模型注册表别名表。
- **阶段验收**：路线文档 G1/G2/G3、B2-02/03/09 各节验收口径逐条过——重点：轮次启动后划分不可变且落审计；授权人=申请人创建被拒；无回执不放量；低 F1/漂移超阈/样本不足/无盲测指标四种情形均拦截。

### S3 · 标注质量链（B2-05 主动学习选样 → B2-06 Kappa+仲裁 → B2-G4 伪标签凭证）

- **最大回归面在 B2-06**：单标注员指派制改「多人标注 + 仲裁」触及标注员门户核心流程，**独立排期窗口 + 完整回归**（简报明确此项为第二批最大回归面），不得与 S2 并行抢带宽。
- **交付物**：九策略选样（熵/Margin/最小置信度等不确定性族补齐，挂 annotation_strategies，初始预算+单轮预算）；Cohen's Kappa 计算 + 冲突仲裁队列 + 整簇纯度门禁（≥0.8 且规模≥10）；伪标签限量（每类按已标真值）+ 降权 + 开发验证比较选择器 + 凭证导出（红线：伪标签永不进终验）。
- **阶段验收**：九策略各有单测、混合按权重出样；冲突样本自动进仲裁、低纯度群无法整簇提交；超限量候选被拒、未胜出方案不被选用、凭证与库内一致。

### S4 · 智能应用（B2-01 审计问答+问数 / B2-04 可信度+CBPE）

- **放在最后**：两者消费前面所有阶段的产出（问答取全库数据、可信度取 MLflow 指标与发布记录）。
- **交付物**：十类审计模板 + 白名单 SQL 问数 + 引用编号全局唯一编号器 + 生成后校验「引用提示与证据清单同表」（竞品 E1/E2 编号跨小节重复是反面教材）；七因子可信度评分 + A–D 档 + 模型卡 11 章节草拟签署（接 S1 审批）+ CBPE 估计口径脚注。
- **M2 收口**：发布治理链全链演练 + S3 回归全绿 + 验收证据 `验收-补齐路线-M2.md/json` + 六 job CI 绿。

## 4. 第三批 · QMS 合规长尾（10 项 · 门控后按单建设）

> **启动门控未过前一行代码不动**（有标书/客户明确要求 + 质量专家评审口径）。以下仅为启动后的内聚顺序建议，按客户点名可跳选：

- **T1 闭环内聚件**（先打通预警→NCR→8D→知识闭环）：B3-04 NCR/CAPA（承接 B1-02「登记 NCR」入口，关闭门禁=连续三验证周期无复发）→ B3-03 8D 报告（D0–D8 顺序推进、D6 未过不得结案、LLM 起草进 B2-08 审计）→ B3-07 案例中心（预警自动开案）→ B3-10 知识库（向量检索反超竞品传统匹配）→ B3-09 批次追溯（批次键源头已在 F1 的 B1-08/B1-10 把关）。
- **T2 报告与控制**：B3-08 质量报告（NG 率/Cpk 从 B1-04/B1-06 同源取数，竞品实测留空是反面教材）→ B3-06 动态控制计划（四因子取数接 B1-09/B1-01/B1-06/B3-04，乘数变更走 S1 审批）。

## 5. 条件启动 · 边缘与 DOE（4 项）

- **严格顺序链**：B4-01 盒子管理（注册/心跳/模型包下发/版本强校验/(box_id, trace_id) 幂等）→ B4-02 设备影子（desired/reported 双状态，即诚实设计⑤正式落地）→ B4-03 灰度/OTA/断网补传（A/B 双槽原子切换、SHA-256 校验、环形缓冲补传、执行器六项检查基线）。
- **B4-04 DOE 独立**：语义防线**先建后开**——ID/序号/编码列在候选生成前拦截（列类型/基数/分布检测）是本模块自身的门控条件；窗口建议强制工程评审意见 → S1 审批 → MES 回执与试产结果必填才可结案。
- 前置动作（不产代码）：盒子代理程序选型（心跳/环形缓冲/幂等上报）、硬件供应链与现场运维能力确认——属非代码前提，启动前单独评估。

## 6. 横向工程合同（全批次统一纪律）

1. **批启动任务 = 技术方案先行**：每批开工第一个动作是 `ml-platform/docs/技术方案-补齐路线第N批.md`（批级一份、分章节按阶段追加详设），评审通过才动代码；阶段开工前把该阶段详设补入同一文档（2026-11-13 文档同步规约：文档与代码同批落、不留待办）。
2. **阶段验收 = 证据入 Git 跟踪目录**：`ml-platform/docs/验收-补齐路线-*.md` + 同名 `.json`；JSON 内区分 passed/failed/skipped/cancelled/not_run/环境阻塞，禁止 continue-on-error 折算成功。
3. **迁移纪律**：ORM 变更必须带 Alembic 迁移 + 迁移头常量同步（单一来源工具链）+ SQLite/PostgreSQL 双兼容 + 旧数据保留断言；模型三件套必须进 `models/__init__` 导入链。
4. **测试纪律**：新后端测试模块/新前端测试文件同批登记唯一周次（week_manifest）；新测试三件套同批提交；前端全量用例本地必跑（CI ubuntu 与本地 Windows 行为有差异，遗留 screen.debug 类语句用完即删）。
5. **前端惯例**：页面标题一律 PageHeading/V2PageFrame；时间解析必须 parseBackendTime；字体自托管（禁 CDN/专有字体）；组件勿用 export {} 列表。
6. **CI 与推送**：推送成功即完成批次汇报（CI 后台监视、结论下批顺带登记）；门禁收敛时 push 前必核 HEAD == 门禁验证过的 head_sha；共享工作树 commit 前必核 branch。
7. **安全扫描预注册**：本路线大量新增含 `def execute(` / `pd.DataFrame(` 的算子与服务文件，Mimosa 误报封锁概率高——新算子文件预注册覆盖绕行；外部输入一律参数化查询（B1-08/B2-01 的 SQL 白名单引擎是唯一例外面，需专门评审）。
8. **对标复算用例即回归用例**：路线文档中所有「竞品实测口径」（SPC 106,504 行取最新 5,000 复算、判据优先级链、PSI 严重 0.25 分级阈值、Cp 组内/Ppk 整体标准差口径）进单测锁死，防口径漂移。
