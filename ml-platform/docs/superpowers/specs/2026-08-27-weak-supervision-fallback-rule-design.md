# 规则侧默认兜底规则设计

## 背景

数据标注的自动标注流程允许用户选择“按规则”或“按簇加规则”策略，并通过“标注规则与标签”配置普通条件规则。当前规则只在表达式命中时覆盖模型输出；没有显式方式表达“除用户规则之外的所有情况”。

本次变更在用户启用规则侧时自动添加一条标签为“其他”的兜底规则。该规则属于规则列表，不可删除，标签名称和值可编辑，但兜底条件不可编辑；每个标签列都必须配置合法兜底值。

## 目标

- 规则侧从关闭切换为启用时，默认追加一条“其他”兜底规则。
- 兜底规则明确表示所有普通规则均未命中的数据。
- 用户可以编辑兜底规则的标签，但不能删除整条兜底规则。
- 普通规则始终优先于兜底规则。
- 前后端使用显式规则类型表达兜底语义，不依赖恒真表达式或规则位置猜测。
- 中文和英文界面均提供完整文案。

## 非目标

- 不增加规则拖动排序功能。
- 不改变未启用规则侧时的模型输出行为。
- 不改变普通规则的表达式编辑能力。
- 不允许通过删除兜底规则来绕过未命中规则的数据覆盖要求。

## 数据合同

普通规则保持现有结构，并显式或隐式使用 `kind: "condition"`。兜底规则使用以下结构：

```json
{
  "id": "fallback-rule",
  "kind": "fallback",
  "labels": {"<label_column_key>": "其他"},
  "tokens": []
}
```

兼容原则：

- 未携带 `kind` 的历史规则按普通条件规则处理。
- `fallback` 规则必须使用空 `tokens`。
- 一次请求最多允许一条 `fallback` 规则。
- 兜底 `labels` 按每个标签列的 dtype、枚举、范围和必填约束校验；历史单值 `label` 只作为迁移输入。
- 后端返回和持久化规范化后的 `kind`，避免消费者再次推断。

## 前端交互

### 自动添加

当规则侧开关从 `false` 变为 `true` 时：

1. 检查当前规则列表是否已有 `kind: "fallback"` 的规则。
2. 若没有，则在列表末尾添加标签为当前语言默认值“其他”或 `Other` 的兜底规则。
3. 若已有，则不重复添加。

切换语言不会覆盖用户已经编辑过的兜底标签。

### 规则卡片

兜底规则沿用普通规则的条件框，但不显示删除操作；以只读说明标识“所有普通规则均未命中”。

- 每个标签列的值均可编辑并单独校验类型。
- 条件区域显示只读说明“除以上规则之外”或 `All other cases`。
- 不显示条件类型选择、数据输入、添加条件或删除条件按钮。
- 不能删除；切换策略或刷新配置时仍保持唯一一条兜底规则，不重复添加。

### 校验和提交

- 普通规则继续校验标签、token 交替结构和至少一个比较运算符。
- 兜底规则只校验每个标签列的值非空且符合对应 schema，不校验 token 表达式。
- `serializedAnnotationRules` 将 `kind` 一并提交。
- 兜底规则必须随 `process_rules` 提交；删除请求由前后端拒绝。

## 后端处理

`normalize_annotation_process_rules` 负责：

1. 将缺少 `kind` 的规则规范化为 `condition`。
2. 按现有逻辑校验普通条件规则。
3. 校验兜底规则标签和空 token。
4. 拒绝未知 `kind`、非空兜底 token 和多条兜底规则。
5. 返回包含显式 `kind` 的规范化规则列表。

`apply_annotation_process_rules` 负责：

1. 按列表顺序计算所有普通条件规则。
2. 第一条命中的普通规则立即返回其标签和命中信息。
3. 所有普通规则均未命中时，返回兜底规则标签。
4. 没有兜底规则或兜底列值不完整时返回配置错误，不保留模型预测结果冒充规则策略结果。

兜底命中的 `rule_hits` 使用该规则的 ID 和标签，并记录稳定原因，便于详情页和审计识别。

## 错误处理

- 空兜底标签沿用 `QUALITY_LABEL_TYPE_INVALID` 或当前标签规范化错误。
- 多条兜底规则、未知规则类型或兜底规则携带表达式统一返回 `QUALITY_ANNOTATION_RULE_INVALID`。
- 前端在正常交互中阻止这些无效请求，后端仍保持独立校验以保护 API 合同。

## 测试

### 前端

- 启用规则侧后自动显示一条“其他”规则。
- 已有兜底规则时重复切换不会产生重复项。
- 兜底条件为只读说明，不显示 token 编辑控件。
- 可以编辑兜底标签并在 validate/create 请求中提交新标签。
- 不能删除兜底规则；删除请求必须被前后端拒绝。
- 数字标签类型下，默认字符串“其他”会要求用户改为合法数字后才能提交。
- 英文界面显示 `Other` 和 `All other cases`。

### 后端

- 普通规则命中时优先于兜底规则。
- 普通规则均未命中时返回兜底标签。
- 没有兜底规则时拒绝配置，不能返回 `None` 绕过兜底合同。
- 规范化接受一条合法兜底规则并补全普通规则 `kind`。
- 规范化拒绝多条兜底规则、未知类型和非空兜底 token。
- API validate/create 接受合法兜底规则并持久化规范化结构。

## 验收标准

- 用户首次启用规则侧即可看到必须保留、可编辑标签的默认“其他”规则。
- 任一数据行只要未命中普通规则且兜底规则仍存在，最终自动标签就是兜底标签。
- 普通规则命中结果不会被兜底规则覆盖。
- 未命中普通规则的行始终使用合法兜底值。
- 聚焦前后端测试、前端生产构建、Python 语法检查和 `git diff --check` 全部通过。
