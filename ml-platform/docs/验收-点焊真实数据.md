# 验收记录：点焊真实数据实验（判据①点焊域小样本复证 + 真实异常检出三族对照）

- 日期：2026-11-13
- 数据：栈内点焊项目 `train_features.csv`（2,072 行真实特征工程数据；73 数值特征列 + `fault` 标签列）
- 口径（**如实标注**）：正常行 1,836 < 判据①门槛 10,000——本实验为「小样本真实数据的机制复证 + 真实异常检出对照」，**非判据①正式达标**；正式达标待 ≥1 万行真实点焊历史数据接入
- 可复现：`ml-platform/backend/tools/acceptance/run_spot_weld_real_experiment.py`
- 结果数据：[验收-点焊真实数据.json](验收-点焊真实数据.json)

## 核心结果：真实异常检出率（236 个 fault=1 真实异常）

| 族 | 阈值 | **真实异常检出** | holdout fpr | 合成·组合异常检出 |
|---|---|---|---|---|
| iforest | 0.631 | **46.2%**（109/236） | 0.0109 ✓ | 0.003 |
| ocsvm | ~0 | **75.8%**（179/236） | 0.049 ⚠️ 超 1.5× 门禁 | 0.000 |
| **autoencoder** | 9.690 | **57.6%**（136/236） | **0.0109 ✓** | 0.000 |

## 解读（数据说话的两个直接证据）

1. **真实异常形态 ≠ 合成构造形态**：合成基准的组合异常（分位错配构造）在拧紧数据上有效（一期 ocsvm 0.79 / AE 0.94），但在点焊数据上三族合成检出≈0；而**真实 fault 异常三族检出 46-76%**——人工构造的「盒角密度空洞」形态在这个点焊数据上不存在，真实劣化走的是其他分布方向。**这是合成基准局限性的直接实证**：合成基准用于排序选型有效，但不能替代真实异常回测。
2. **族排序随数据分布变化**：拧紧数据 AE 领先（comb 0.94），点焊数据 ocsvm 领先（真实检出 75.8%）、AE 次之（57.6% 且 fpr 达标）——**「三族同台搜索 + 数据说话选族」的架构决策被两个域的真实数据双向验证**。
3. **ocsvm 的 fpr/检出权衡**：ocsvm 真实检出最高但 fpr 超门禁 3 倍——contamination 先验需要按点焊域调高（当前 0.01 对该数据偏严），这正是向导暴露 contamination 参数的设计意图。
4. **AE 首次真实数据表现**：57.6% 检出 + fpr 达标（与 iforest 同为 0.0109）——真实数据上 AE 不是最优族但为可用族；结合拧紧域 comb 0.94 的领先表现，「三族同台、按域数据选族」仍是正确策略。

## 与判据的关系

- 判据①（点焊域）：**行数门槛不满足**（1,836 < 10,000），本实验不构成正式达标；机制（三族训练/标定/检出评估）在点焊域完整复现，待真实历史数据（≥1 万行）接入后按同脚本正式达标
- 判据③（真实异常检出）：**增强实证**——此前以合成对照落档，本实验首次用 236 个真实 fault 标签检出（阈值法基线对比与详细误报分析待 fault 标签质量核验后补充）
