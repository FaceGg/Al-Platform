### 二、实施原则（五条）

1. **门控式分批，不做一次性全量**：37 项并行开发会挤占 AutoML/工作流/LLM 主线迭代带宽，且含竞品实测空壳功能（NCR/SCAR/控制计划 0 记录）——按批交付、按批验收。
2. **闭环要真转，不是有页面**：竞品的教训是机制完备度 4.2/5 而实例活跃度 1.9/5。每个模块的验收口径都包含「真实数据走一遍」，且利用我方三端标注运营的真实流量。
3. **证据必须进 Git 跟踪目录**：工序平台把验收回执放 gitignored runtime/ 是反面教材；本路线所有验收回执 JSON/日志落 docs/验收-*.json（仓库 AGENTS.md 既有规则）。
4. **诚实设计随批落地**：陈旧数据自检横幅、口径脚注、空态引导、审批过期回收、设备影子——五项产品语言改造成本低，逐页随批带上。
5. **对标有实测证据的才抄**：借鉴清单每项都标注对方实现证据（竞品 20 页交互实测 / 工序代码级确认）；竞品「宣称有但实测空转」的模块（如知识库）只抄规则设计，不抄运营预期。

## 第一批 · 闭环运营必需集（13 项 + 诚实设计 5 项）

> 启动门控：立即启动。做完即可与竞品正面对打——其机制全但「无人转」，我方有三端标注运营让闭环真转。随批「抄作业」五项诚实设计逐页带上。

### B1-01 预警中心

> 对标：竞品·质量预警中心（实测：机制真实、数据空转——14 条全部待确认 + SLA 超时）

- **功能**：六类预警来源归一列表（曲线偏离 / 参数超限 / SPC 判异 / 模型风险 / 传感器 / 设备异常），支持行级查看、确认、分配，勾选批量操作与 CSV 导出。
- **流程**：推理/规则/SPC 产生事件 → 事件流写入 alerts → 中心聚合展示 → 筛选定位 → 确认或分配责任人 → 转处置工作台 → 处置结论回流。
- **实现细节**：
  - **数据**：alerts 表（id/来源类型/风险级别/关联工位/设备/批次/处置状态/责任人/sla_due_at/证据 JSON）；处置轨迹表（见 B1-02）。
  - **API**：新 router（列表分页、筛选枚举、批量确认、分配、导出）；风险阈值（高 0.85 / 严重 0.95，参照竞品页面可配）。
  - **复用**：闭环事件流写入侧挂接；通知中心承接 SLA 临期/超时推送。
  - **防呆**：竞品实测责任人为空导致 14 条全超时无人认领——确认动作强制填写责任人（防呆优于竞品）。
- **验收口径**：合成事件从产生→确认→分配→处置全链可追溯；SLA 临期自动通知送达；责任人为空时确认按钮置灰。

### B1-02 异常处置工作台

> 对标：竞品·异常处置工作台（实测：判据引擎真实、附件「未配置」、缺曲线列）

- **功能**：单预警五阶段流转（待确认→已确认→处理中→待复核→已关闭）+ 独立误报处置；证据区并列实测值 / 基线 / 规格上下限 / 模型依据；可登记 NCR（第三批接口预留）、转交、请求复核。
- **流程**：从预警中心点入 → 证据区核对（判据优先级：规格超限 → 3σ 超限 → 2σ 偏离 → 基线偏离 30%）→ 确认异常或误报 → 填写处置表单（类型/原因/措施/停机/返工/扩大检查标记）→ 提交 → 轨迹逐条追加。
- **实现细节**：
  - **数据**：alert_events 轨迹表（阶段/操作人/时间/备注/表单快照）；误报样本回流标注队列。
  - **判据**：固定优先级判定引擎照抄竞品口径（实测可复算），每条预警展示命中判据链。
  - **曲线**：时序波形叠加样本与目标窗口——竞品实测点焊预警缺曲线列无数据可叠，我方数据接入强制带波形列（B1-10 字段角色把关）。
  - **附件**：处置照片/文件接 MinIO（竞品实测「未配置」是反面教材）。
- **验收口径**：每条预警有完整阶段轨迹；误报结论自动进标注回流队列；带波形样本可叠加目标窗口。

### B1-03 质量 KPI 驾驶舱

> 对标：竞品·质量驾驶舱（实测：下钻真实、KPI 卡齐全）

- **功能**：产量 / 正常数 / 已确认 NG / AI+SPC 预警 / 待处理 / 高风险六卡 KPI + 七天预警走势 + 风险分布 + 最近异常 + 工位风险排名 + 产线状态分布；命中率口径页内注明（已确认异常 ÷ 已关闭预警）。
- **流程**：进入驾驶舱 → 顶栏四级范围（工厂→车间→产线→场景）联动切换 → KPI 卡下钻直达生产监控 / 预警列表 / 趋势 / NCR / 报告。
- **实现细节**：
  - **数据**：聚合查询 API 基于 alerts + 推理结果表同口径 SQL——竞品实测出现趋势页与日报数字口径打架，我方 KPI 与列表页共用同一聚合视图。
  - **复用**：React 图表组件库；报表导出复用 B1-12 证据链打包。
  - **诚实设计①**：陈旧数据自检横幅（距最后推理超 24h 自动挂出——竞品「自曝」设计照抄）。
- **验收口径**：KPI 数字与下钻列表页严格一致（同一 SQL 视图单测）；四级范围切换全卡联动。

### B1-04 质量趋势与帕累托分析

> 对标：竞品·质量趋势分析（实测：Top NOK 为空而日报有数据——口径打架反面教材）

- **功能**：NG 率走势、SPC 超限统计、缺陷帕累托（按预警预测标签 + NG 词表）、按设备 / 工位 / 产品 / 批次多维护对比。
- **流程**：选范围与时间窗（7/30/90 天）→ 出趋势与帕累托 → 切换对比维度 → 导出/打印。
- **实现细节**：
  - **词表**：NG 词表配置化（竞品按「预警预测标签及 NG 词表」统计）——词表与 B3-08 质量报告共用一份配置，杜绝口径分叉。
  - **复用**：推理结果表 + alerts 聚合；图表组件复用驾驶舱。
- **验收口径**：趋势页缺陷计数与日报（B3-08）同数据源同数字；帕累托 Top N 与 KPI 卡「最近异常」一致。

### B1-05 实时生产监控

> 对标：竞品·实时生产监控（实测：树联动真实、设备标识缺省、状态由记录推导）

- **功能**：产线 / 工位 / 设备三级树 + 工位卡（产品、批次、最新生产时间、OK/NG、班次产量、风险分数、现场参数及参考值）；本班次未关闭事件；「确认收到」「呼叫质量人员」入口。
- **流程**：选工位 → 卡片实时刷新（自动/手动）→ 异常事件就地确认或跳预警 → 处置流转。
- **实现细节**：
  - **推送**：复用闭环事件流做 SSE/WebSocket 推送，新事件 5 秒内上屏。
  - **设备台账**：设备注册直接落库（竞品设备树由最新推理推导、未落库——反面教材）；心跳与连接状态来自 B1-10。
- **验收口径**：模拟事件 5 秒内上屏；确认收到动作留痕；设备离线状态准确反映心跳。

### B1-06 SPC 过程控制

> 对标：竞品·SPC 过程控制（实测：全套中最扎实的一页，口径可复算）

- **功能**：变量图 X-bar R / X-bar S / I-MR，计数图 P / NP / C / U；Nelson 1–8 判异开关；控制限 / 规格限 / 受控率 / 判异明细 / 直方图 / 趋势；能力指数全套 Cp / Cpk / Pp / Ppk / Cpm / Cr / σ 水平 / 估计 PPM，缺规格限自动留空。
- **流程**：选数据源（数据集 / 推理结果 / 实时）→ 选过程参数与分析窗口 → 子组容量 2–10、USL / LSL / 目标值 → 出图 → 点击越界点位看判异明细。
- **实现细节**：
  - **口径**：Cp 用组内标准差、Ppk 用整体标准差（竞品脚注口径照抄——诚实设计②）；判异规则单元测试全覆盖。
  - **复用**：数据集服务取数；统计公式纯函数库可独立测试。
  - **对标复算**：竞品示例（106,504 行取最新 5,000、5 样本/组 = 1,000 点、1 越界 + 43 规则警告）作为我方回归用例。
- **验收口径**：竞品同口径数据复算一致；8 类判异各有单测；缺规格限时能力指数留空不报错。

### B1-07 Kafka 实时接入

> 对标：竞品（实测：Kafka 状态表标「告警」、实时链路从未启动）

- **功能**：可选部署 profile 的 Kafka 实时链路：topic 消费 → 解析 → 推理 → 事件流 → 预警。
- **流程**：场景配置（B1-10）声明数据源 schema（时间字段 / 分组字段 / 目标字段）→ consumer 按场景订阅 → 批量/单条推理 → 写事件流。
- **实现细节**：
  - **部署**：compose 可选 profile，不加重默认栈——竞品 Kafka「宣称在、从未转」的教训：不上真实流量就不实背中间件。
  - **幂等**：按业务样本 ID 幂等去重（工序 (trace_id) 幂等实践），重放不产生重复预警。
  - **诚实设计⑤变体**：全站页脚实时链路状态（未启动/正常/告警）——竞品设计照抄。
- **验收口径**：端到端延迟秒级；重放消费不重复计数；链路状态页脚真实反映。

### B1-08 外部数据库直连

> 对标：竞品·数据源（实测：机制真实、暂无已配置数据源；界面限 SELECT/WITH）

- **功能**：MySQL / PostgreSQL 只读数据源接入：连接测试、表浏览、预览、导入为数据集。
- **流程**：新建数据源（主机/库名/只读账号）→ 连接测试 → 表浏览与预览 → 按字段角色导入数据池。
- **实现细节**：
  - **安全**：界面仅允许 SELECT/WITH 白名单查询；连接口令 Fernet 加密仅后端保存（竞品口径 + 工序 crypto 实践）；只读账号权限校验。
  - **复用**：SQLAlchemy 多引擎；数据集服务承接导入。
- **验收口径**：白名单外 SQL 拒绝并落审计；口令任何接口不回显明文。

### B1-09 独立漂移监控页

> 对标：竞品·模型漂移（实测：唯一自动运转的能力——当日 PSI 4.454、39/89 特征漂移）

- **功能**：PSI（单变量分布差异）+ PCA 重构误差（多变量）+ DQ 检查（字段结构 / 缺失率 / 类别基数突变）三类检测；报告列表按严重/关注分级、特征级明细可展开。
- **流程**：定时批检（扫描周期可配，参照竞品 60s）→ 产出分级报告 → 严重级推送通知 → 一键转重训提案（进第二批审批流）。
- **实现细节**：
  - **数据**：drift_reports / drift_report_features 表；阈值参照竞品（严重 0.25 / 关注档）可配。
  - **复用**：PSI 从现有闭环事件流抽出独立化（不重写算法，重组织报告与页面）。
  - **回放**：历史推理可回放检测；实时窗口检测入口随 B1-07 联动。
  - **口径**：默认「观察信号」不自动处置（竞品口径照抄——漂移是触发器不是自动开关）。
- **验收口径**：定时批检真实产出报告（对标竞品实测运转状态）；严重级报告自动通知；特征明细可展开复算。

### B1-10 场景与设备管理

> 对标：竞品·场景与设备管理（实测：三页签真实、设备树未落库、采集接口空）

- **功能**：场景配置（编码 / 工序 / 数据源 / 标签体系 / 时间与分组字段 / 窗口策略 / 参数单位与上下限）+ 设备台账（协议 / 状态 / 心跳 / 连接）+ 字段角色（ID / 分组 / 时间 / 目标 / 特征 / 忽略 / 附加）。
- **流程**：建场景 → 绑数据源与字段角色 → 注册设备（支持从推理记录同步工位）→ 心跳监测 → 供训练与预警引用。
- **实现细节**：
  - **字段角色**：目标 / ID / 时间 / 分组字段默认排除出模型输入（竞品规则照抄——接特征工程管道）。

### B3-02 FMEA

> 对标：竞品（实测：S/O/D、服务端算 RPN、措施可同步控制计划）

- **功能**：失效模式库维护 S / O / D，服务端计算 RPN；纠正措施可一键同步到动态控制计划（B3-06）对应质量点。
- **验收口径**：RPN = S×O×D 服务端计算（防前端篡改）；同步控制计划生成待审批变更。

### B3-03 8D 报告

> 对标：竞品（实测：D0–D8 顺序推进、D6 验证通过方可结案；竞品动作审计里唯一一条记录就是 8D 草拟成功）

- **功能**：案例关联的 8D 报告：D0–D8 分步顺序推进，D6（永久对策验证）通过后方可结案；LLM 起草草稿（复用 LLM 网关）；复发检测 + 证据包导出（接 B1-12）。
- **实现细节**：
  - **复用**：LLM 网关生成 D1–D5 初稿（竞品 8D 草拟是其唯一真实智能体动作——抄并加强）；逐步人工确认。
- **验收口径**：跳过 D6 直接结案被拒；LLM 草稿进 B2-08 动作审计；复发检测命中提示重开。

### B3-04 NCR / CAPA

> 对标：竞品（实测：五阶段 + 早期驳回 + 关闭门禁=连续三验证周期无复发；全项目 0 条）

- **功能**：不合格登记（手工或从预警转入）→ 根因分析 → 纠正措施 → 有效性验证 → 关闭五阶段；早期可驳回；关闭门禁 = 连续三个验证周期无复发。
- **实现细节**：
  - **联动**：预警处置工作台（B1-02）「登记 NCR」入口打通；复发判定接 SPC / 预警数据。
- **验收口径**：三周期未满关闭被拒；从预警转入自动带证据链；驳回留理由。

### B3-05 供应商协同 · IQC → SCAR

> 对标：竞品（实测：约束校验在位——检验数≤来料数、不良数≤检验数；IQC 不合格自动生成唯一 SCAR；台账 0）

- **功能**：供应商与编码台账（停用即停止登记新来料）；来料批次 IQC 检验（数量约束校验）；IQC 不合格自动生成唯一 SCAR，按原因 / 纠正 / 验证 / 关闭推进，执行人与时间留痕。
- **验收口径**：数量约束校验单测；一检验一 SCAR 唯一性；停用供应商新来料被拒。

### B3-06 动态控制计划

> 对标：竞品（实测：唯一生效版 + 四因子加严 + 决策流水；0 条记录待用实际计划验证）

- **功能**：同项目仅保留一份生效计划（新版生效旧版归档）；维护质量点与基础抽样量；按漂移 / 预警 / 过程能力 / 复发四因子评估抽样加严，较高建议乘数进待审批（接 B2-07）；现场按质量点查询最后一条已生效指令；决策流水保留窗口 / 各因子 / 权重 / 理由。
- **实现细节**：
  - **复用**：四因子取数分别接 B1-09 漂移 / B1-01 预警 / B1-06 Cpk / B3-04 复发记录。
- **验收口径**：同项目双生效计划被拒；乘数变更必经审批；决策流水可复算乘数。

### B3-07 案例中心

> 对标：竞品（实测：预警自动开案 1 例真实、16 案例全部未结、可关联下游处置与 NCR 重推状态）

- **功能**：预警自动开案或手工开案；按项目 / 状态 / 关键词 / 时间 / 严重度检索；展开见关联对象与时间线；可依据下游处置或 NCR 进度重推状态；详情关联处置 / 根因 / NCR / 知识案例 / 报告 / 模型卡 / 控制计划版本。
- **验收口径**：预警→自动开案→关联 8D/NCR 全链；状态重推规则单测。

### B3-08 质量报告

> 对标：竞品（实测：日报 HTML/JSON 导出在位、11-14 日报记录 14 条预警但平均 NG 率与 Cpk 留空——口径缺口反面教材）

- **功能**：日报 / 周报 / 月报定时生成 + 手工补报；内容含预警总量与趋势、NG 率、Cpk 达标率、Top 缺陷与设备、NCR 概况；HTML / JSON 导出。
- **实现细节**：
  - **口径**：NG 率与 Cpk 从 B1-06 / B1-04 同源取数——竞品实测报告指标留空，我方必须保证口径接线后「有数」。
- **验收口径**：报告数字与趋势页同源一致；NG 率 / Cpk 有值（有 SPC 数据时不再留空）；定时任务真实产出。

### B3-09 批次追溯

> 对标：竞品（实测：样本追溯+批次概览入口在位，但推理数据缺批次字段——链路查询不完整是反面教材）

- **功能**：样本追溯（业务样本 ID 串起原始数据、模型判定、预警与 NCR）+ 批次概览（按批次列口径看质量）。
- **实现细节**：
  - **关键**：批次键在数据接入（B1-08 / B1-10 字段角色）强制维护——竞品因缺批次字段导致追溯空转，我方从源头把关。
- **验收口径**：单样本四对象串联查询；无批次键的数据集在接入时报错而非静默。

### B3-10 质量知识库

> 对标：竞品（实测：机制真实、案例库空态——症状查 Top 5 相似入口在位）

- **功能**：沉淀缺陷代码 / 现象 / 根因 / 措施 / 有效性验证结论；关键词 / 缺陷代码 / 设备筛选；症状查询 Top 5 相似案例与匹配原因；预警详情与 8D 草稿可引用知识条目。
- **实现细节**：
  - **复用**：RAG/向量库做相似检索（LLM 网关基建已有——竞品为传统匹配，我方用向量检索反超）。
- **验收口径**：症状查询返回 Top 5 带匹配原因；预警与 8D 引用留痕。

## 条件启动 · 边缘与 DOE（4 项）

> 启动门控：真实边缘订单（硬件供应链与现场运维能力就绪）/ DOE 特征语义防线就绪。唯一带非代码前提的批次。

### B4-01 推理盒子管理

> 对标：竞品（实测：单盒注册在位——点焊边缘盒子、ONNX 包 89.6 KB、心跳、设备影子）

- **功能**：盒子注册 / 心跳监测 / 模型包下发（ONNX 统一导出 + 场景/特征版本强校验）/ 管理页。
- **实现细节**：
  - **复用**：本平台 ONNX 转换/导出已有，缺盒子代理程序（心跳 / 环形缓冲 / 幂等上报）与管理页。
  - **设计**：场景与特征版本强校验照抄竞品（版本不匹配拒载）；(box_id, trace_id) 幂等键设计照抄。
- **验收口径**：盒端下载模型包→版本校验→加载打分→回执全链；心跳断线管理页告警。

### B4-02 设备影子

> 对标：竞品（实测：desired/reported 双状态在位）；即诚实设计⑤的正式落地

- **功能**：每盒子维护 desired（平台期望配置/版本）与 reported（实际状态）双状态文档；平台只写 desired，盒端同步后回报 reported，差异可见。
- **验收口径**：desired 下发后 reported 回报一致；中间态（下发未确认）可见可干预。

### B4-03 灰度 / OTA / 断网补传

> 对标：竞品（A/B 双槽原子切换、OTA 校验、失败回滚）；安全基线抄工序（Job Object 执行器隔离 6 项检查）

- **功能**：A/B 双槽模型原子切换（失败自动回滚）；OTA 包校验（SHA-256）；断网期间数据环形缓冲、恢复后补传（幂等去重）。
- **实现细节**：
  - **执行器基线**：盒端打分子进程隔离 + 内存 / 超时 / 结果契约 / 产物 / 日志上限六项检查（工序 S8-03 实证基线照抄）。
- **验收口径**：坏包 OTA 校验失败拒装并回滚；断网→恢复→补传不重不漏；资源上限触发被杀留日志。

### B4-04 工艺参数优化（DOE）

> 对标：竞品（实测反面教材：3 条建议全部作用于疑似 ID/序号列 wldindex，期望 NG 率 0.0%，MES 工单全空——对特征语义无任何防御）

- **功能**：按项目 / 数据集 / 参数预览响应曲线 → 生成带审批的可行窗口建议（≥100 条样本前提，受规格限与最大调整幅度双重约束）→ 建议 → B2-07 审批 → MES 配方变更 → 试产结果回填（试产批次按 ID 去重）。
- **实现细节**：
  - **语义防线（先建后开）**：参数列准入校验——列类型 / 基数 / 取值分布检测拦截 ID、序号、编码列（竞品「百万级取值 ID 列推 0% NG 窗口」是本模块的门控条件，防重蹈覆辙）。
  - **联审**：窗口建议强制工程评审意见后才能进审批（竞品口径「需工程评审」保留且真执行）。
  - **闭环**：MES 工单回执与试产结果必填才可结案（竞品实测 MES 工单全空——我方补对端回执确认）。
- **验收口径**：ID/序号列在候选生成前被拦截并给理由；无评审意见的建议不能提交审批；MES 回执留痕。
