### 9.3 判据引擎与 SPC 基线冻结（E08）

- 判据优先级链（照抄竞品口径，可复算）：**规格超限 → 3σ 超限 → 2σ 偏离 → 基线偏离 30%**；`evaluate_criteria_chain(db, alert) -> list[{criterion, hit, detail}]`：
  - 规格超限：读 quality_spec_limits（当前值，D20）对 evidence.recorded_value（字段+统计量）判 USL/LSL；
  - 3σ/2σ：**绑定冻结基线**——active 基线（同 station/condition/field），无冻结基线 → 该两级判据返回 skipped + 提示「未冻结基线，仅规格判据」（路线口径）；
  - 基线偏离 30%：|v−center|/|center| ≥ 0.30。
- 基线冻结 API：POST `/quality-scenes/{id}/spc-baselines` {station_id?, condition_value?, field, statistic?, window_start, window_end} → 服务端从 inference_results 取窗口数值（evidence 无值的行用 predicted_value/anomaly_score 亦可作 field 数据源——首版 field=特征列名时从快照/明细推断，明细无数值特征 → 从场景绑定数据集取数），I-MR 口径计算（中心=均值，σ=平均移动极差/1.128）；校验 20–500 与恒定拒绝；同键版本递增、旧版本失效。GET 列表含历史版本。
- 首版取数实现注：若 scene 绑定数据集（data_source_id → 外部源，或场景关联数据集版本），field 数值从数据集行取；推理明细无数值列是已知限界（D19），详设落此，不夸大。

### 9.4 SOP 版本化与处置单快照（E07）+ 误报回流（D22）

### 9.11 实施修订记录（2026-11-26，F2a 后端 Q1–Q3 落码时的更正；原设计表述保留，以本节为准）

落码与测试中发现的原设计缺口，逐条更正如下；每条都有对应测试锁住。

1. **合并键须含「原因」判别因子**（修订 D15）。原设计合并键只到来源类型，两个不同参数同时超限会被并成一条预警。实现为 `quality_alerts.merge_key`（来源类型 + 判别因子：`param_exceed:field=<字段>`、`model_risk:deployment=<部署>`、`device_anomaly`、`demo:<配置>:<类型>`）加 `merge_open` 列；同因 = 同项目 + 同合并键 + 同归属（场景/工位/设备/工况/演示标记）。合并时严重级别只升不降，每次发生的明细留在 `occurred` 轨迹里供组内展开。
2. **无监督模型的触发依据**（补充 D14）。异常分数的量纲因族而异，只拿分数比固定触发阈值会让无监督部署的预警中心静默失效。实现为「分数 ≥ 触发阈值 **或** 模型判异（is_anomaly）」即触发，依据写入证据 `rule`；分数不在 [0,1] 时不套用比例型分级阈值，直接记 high。
3. **基线数值由服务端取出**（修订 §9.3「取数实现注」）。不让客户端传数值——服务端无从复算，达不到「所引用的事件序号可追溯」。冻结请求指定数据集版本与稳定时段（行号范围走 SQL 过滤，工况值与时间窗在取数时过滤），服务端按行序取数并做 I-MR 计算与校验；`reference` 记录数据集版本、内容哈希与首末样本。命中样本超过 500 直接报错让调用方缩小范围，不静默截断。
4. **判据链的基线查找带回退**：工位+工况精确 → 工位级 → 工况级 → 场景级，取第一个活动版本。
5. **处置单快照收录当时生效的全部 SOP**（修订 §9.4）：一个场景可能有多个编号的 SOP，全部记录而不是任意挑一个；预警无工况值时不收「只适用于某工况」的 SOP，无场景时只收项目级 SOP。
6. **设备恢复的状态语义**（修订 D16）：恢复时恰好记一条 `device_recovered` 轨迹并把预警置为 `merge_open=false`——原实现每轮巡检都会追加一条恢复轨迹，且恢复后的新一次离线会并进旧预警。恢复仍不自动关闭预警。
7. **附带动作用保存点隔离**：推理落库里的预警评估、处置里的误报复核任务创建，都在 `SAVEPOINT` 里执行。原实现失败时会回滚整个会话——处置结论本身会被一起丢掉；PG 上失败的语句还会中止事务，连带明细落库失败。复核任务可选同时指派标注员（`review_annotator_ids`），不传则建成待指派状态。
8. **落库行与特征行成对传入**：日量超限会跳过正常样本，事后按两个平行序列对齐会错位；改为在构造明细行的同一次遍历里配对。
9. **轨迹顺序确定**：同一预警的轨迹时间戳严格递增（一次处置里「流转」与「处置提交」原共用同一时间戳，只靠时间排序先后不确定）。流转轨迹记录真实的「从状态」；离开 `open` 即记 `first_ack_at`（E09 起算点）；责任人防呆对所有流转生效。
10. **曲线叠加的取数与解码**：样本查找限定在本项目内（样本键不是全局唯一的，原实现会跨项目取数）；波形解码用通用实现（平台波形列约定：base64 的大端 int16 序列，不限点数），不引用点焊域特征模块（泛化门禁）；目标窗口返回该波形列的全部规格统计量（E27）。
11. **聚合桶回写不凭空造桶**：找不到对应小时桶就不写并如实返回 `bucket_confirmed=false`——造一个 total=0 的桶会破坏「桶数字 = 明细计数」的不变式。
12. **接口错误载荷统一**为 `{code, message}`：`code` 是干净的机器可读码，中文说明放 `message`。预警规则设置校验的是「与平台默认合并后的完整规则」，只存显式配置的键。创建 SOP 时校验场景属于本项目（404）。
13. **顺手修复**：`api/agent_extras.py` 两处 fallback 分支 import 路径（F1 验收 §4 登记项）。
14. **预警列表补 `sla_overdue` 筛选**（已超时且仍未处置完）：预警中心与处置工作台的「SLA 超时」卡读它，驾驶舱的同名口径与此同源。
15. **前端落地形态**（补充 §9.8）：预警规则原设计未定页面，落在「SOP 维护」页的第三个页签（SOP 版本 / SPC 基线 / 预警规则，配置组不新增菜单）；处置工作台经 `?alert=<id>` 直达某条预警；批量确认与单条确认共用「未选责任人时确认不可用」的防呆；同因展开读该预警的 `occurred` 轨迹；处置抽屉的「登记 NCR」为置灰预留入口并注明随第三批接入；无波形时给出原因与第一步（诚实设计③）；风险分口径脚注在预警中心页尾（诚实设计②）。
16. **既有用例随内容变化更新**：帮助中心的 F1 搜索用例原以「规格定义」做唯一定位词，新增的预警/处置两章也讲规格定义，改用只出现在场景管理章的「字段角色」；侧栏分组快照随新菜单项更新。
17. **证据总览的环节状态由三态扩为五态**（修订 D24）。平台当前根本不产出证据的环节——切分（随第二批划分管理）、主动选样（随第二批）、现场验证（随第四批盒端回执）——如果标成「缺失」或「待发生」，等于把「平台没做这件事」说成「这个模型缺证据」。实现为 complete / pending / missing / **not_supported**（平台当前版本不产出，注记写明随哪一批接入）/ **not_applicable**（外部导入模型没有平台训练记录）。每个环节带可下钻的依据引用（数据集版本、训练任务、标注任务、部署等）。
18. **上线检查的校验和项分两档**：总览接口只看模型工件是否登记了有效的 SHA-256（并在明细里写明「未重算」）；「留档」动作重新读取模型文件计算哈希并与登记值比对，文件被改动会报失败。生产版本唯一按「同一已注册模型下处于运行态的版本数」判定。
19. **证据包的边界**：审计日志只在调用方持有 `audit.read` 时随包（普通处置角色导出不含审计）；模型文件本体随包有体积上限（64MB，超过只放元数据与校验和并在包内写明）；按预警打包含处置轨迹、判据链（按导出时的现行规格复算并注明）、触发它的推理明细及其模型版本的证据；清单 `MANIFEST.SHA256` 用两个空格分隔，`sha256sum -c` 直接可校验；包注册为平台工件（type=evidence_export）并落审计，下载端点按项目鉴权。

实施记录：

1. **直方图必须覆盖全部样本**：落库路径里直方图的范围元组是为每条记录单独记的，没有复用「明细行」列表——超限降级时明细只留异常与抽样，拿它累计会得到有偏分布。用例经真实落库路径验证：超限降级下 60 条样本一条明细都不落，直方图仍累计 60 条。
2. **基线是惰性计算的**：第一次遇到某个模型版本时按血缘从训练数据集版本取至多 5 万行计算并落库，之后进程内缓存；没有血缘的结果也缓存 10 分钟，避免每次落库都去查血缘。代价是某个模型版本上线后的**第一笔**落库会在后台线程里多花几秒读训练数据。
3. **常量特征的退化基线**：训练时恒为某个值的特征，基线是 `[v, v]`；观测值不等于 v 的归到「箱外」。不做这个处理，常量特征永远判不出漂移。
4. **「集中在单一分箱」与漂移会同时出现**：分布整体平移到最高箱时，PSI 判严重漂移，同时取值也都集中在训练分布的同一个分箱里。两个信号都是事实，报告里都保留；预警标题的措辞是「取值全部集中在训练分布的同一个分箱内」，不说「恒值」（是否真的恒值，从分箱计数分辨不出来）。
5. **实时 3σ 判异的一处缺陷（测试发现并修复）**：新加的 SPC 判异调用把场景、工位等归属参数传了两遍，运行时抛类型错误。保存点按设计兜住了——明细落库不受影响——但**该次请求的整段预警评估被撤销**，模型风险与参数超限预警也会一起丢。经真实落库路径的用例「越冻结基线限产生 SPC 判异」拦住；这条用例同时断言被吞掉的评估异常不再出现。
6. **SPC 控制限用常数表**：X-bar 图的控制限直接取 A2·R̄ / A3·S̄，不用 3σ/√n 反算（表值只保留三位小数，两者末位有舍入差）；样本量不等时 U 图的中心线是加权平均。两处都是写测试时用手算向量核对的。
7. **漂移报告如实写明未接入的信号**：报告 `summary.not_wired` 固定列出 PCA 重构误差、分数级 PSI 并入报告、分片按版本分桶（D39），测试断言该字段存在——防止以后被悄悄当成已做。

## 12. 风险与限界

| 风险/限界 | 处置 |
|---|---|
| 训练挂钩触及 AutoML 核心路径（automl_execution.py:3089） | 默认行为零变化 + F1 内独立跑 AutoML 全量回归；S2a 在同一入口扩展避免改两次 |
