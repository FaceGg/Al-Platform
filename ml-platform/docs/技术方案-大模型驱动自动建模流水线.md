# 技术方案：大模型驱动的自动建模流水线（AutoML Agent）

> 版本：v0.1（2026-10-21）
> 定位：在现有"电焊闭环 + 拧紧闭环"能力之上，把**数据分析 → 特征工程 → 自动建模 → 评估验收**四步
> 交给大模型（LLM）驱动的智能体自动迭代，验收通过后固化为可复用的**建模配方（Pipeline Recipe）**，
> 新数据到来时按配方自动重跑，人工只做最少把关。
> 现状基线：数据集与目标列已就绪（电焊 `fault`、拧紧 `DECIDE(判定…)`），推理部署与回流换模闭环已可用。

---

## 一、设计目标与原则

1. **大模型当"数据科学家"用**：负责分析、决策、写特征工程代码、写评审结论；**不负责数值计算**——
   所有统计、训练、指标一律由平台确定性工具执行，LLM 只读工具产出的结构化报告做判断。
2. **每个 LLM 输出必须是可校验的结构化 JSON**（分析报告 / 特征脚本 / 评审结论三类契约），
   校验失败自动重试，杜绝自由文本流入执行链路。
3. **迭代有界**：分析→特征→建模→评估最多 N 轮（默认 3），每轮失败原因写入"迭代记忆"供下轮改进；
   超限转人工并附带完整过程档案。
4. **固化产物可版本、可审计、可复用**：配方是一等公民，等价于现在的工作流模板，
   能被新数据集、回流重训、甚至新产线（换域名特征）调用。
5. **人在回路的三个最小介入点**：目标列与硬指标确认（一次性）、验收门禁失败升级、最终发布批准。

## 二、与现有平台的关系（复用清单）

| 现有能力 | 在新流程中的角色 |
|---|---|
| 数据集 + 目标列（电焊 fault / 拧紧 DECIDE） | 流程输入（Step 0 已完成） |
| `spot_weld_features` / `tighten_feature_engineering` 算子 | 领域特征工程的"参考实现"，LLM 生成脚本的对照基线 |
| 沙箱 Python 脚本算子（utility_operators.PythonScript） | LLM 生成特征脚本的**唯一执行通道**（资源/超时受限） |
| AutoML（optuna 贝叶斯 + 8 算法族 + 分层 CV） | Step 3 建模引擎，零改动复用 |
| `_native_feature_importance`（已持久化进 metrics） | Step 4 的特征重要性证据 |
| LLM 网关（`settings.llm_api_url/key/model`，chat.py 的 httpx 调用模式） | 智能体的推理引擎 |
| 知识库（点焊标准法规 KB 等） | Step 1 的领域知识注入（RAG） |
| 工作流引擎 + 全局模板 | 配方的执行载体与固化载体 |
| 闭环回流 → 重训 → 换模 | 配方固化的下游消费者（回流数据按配方自动重跑） |

## 三、总体架构

```
┌────────────────────────────────────────────────────────────────────┐
│                     AutoML Agent（编排器，新增服务）                  │
│  while 轮次 <= N 且 未验收:                                        │
│   S1 数据智能分析 ──→ S2 特征工程生成 ──→ S3 AutoML ──→ S4 评审验收  │
│        ▲                                                    │       │
│        └────────── 不满足：失败原因写入迭代记忆 ←──────────────────┘       │
│  验收通过 → 固化 PipelineRecipe（版本化模板）→ 发布/订阅回流重训          │
└────────────────────────────────────────────────────────────────────┘
   每步 = LLM(结构化输出) + 平台确定性工具；全链路事件流 + 产物落盘可审计
```

### S1 数据智能分析（LLM + 数据画像工具）

**工具先行**：平台先计算数据画像（不依赖 LLM）：
- 基础统计：行数、列数、每列类型/缺失率/基数/最小-最大/分位数；
- 目标列：类别分布（不平衡度）、标签语义（列名注解，如"0-不合格，1-合格"）；
- 相关性：与目标列点二列相关 / 互信息 Top-K；列间高相关对（>0.95）；
- 领域分组：按列名聚类到领域通道（电焊：电流/电压/电阻/功率/能量/飞溅/熔核；
  拧紧：扭矩/目标扭矩/上下限/双轴/程序号/作业时间），复用列名基础名解析规则。

**LLM 输入**：数据画像 JSON + 目标列语义 + （可选）知识库检索片段 + 上一轮迭代记忆。
**LLM 输出契约**（`AnalysisReport`，JSON Schema 校验）：

```json
{
  "domain": "tightening | welding | ...",
  "target_semantics": "0=不合格，1=合格",
  "focus_channels": ["torque", "dual_axis", "margin"],
  "expected_important_features": [
    {"name_hint": "TIGHTEN_LOWER_MARGIN", "reason": "贴下限即欠拧风险", "priority": "high"}
  ],
  "data_quality_actions": [
    {"column": "ACTUAL_TORQUE_TWO", "issue": "单轴行缺失", "action": "median_fill+missing_flag"}
  ],
  "leakage_suspects": ["DECIDE_ONE", "DECIDE_TWO"],
  "class_balance_concern": "20.5% 不合格，可用 class_weight",
  "feature_engineering_brief": "推导偏差/带宽比/上下裕度/双轴差，并保留缺失标记"
}
```

电焊示例预期：LLM 应指出电流/电压/电阻/功率四通道波形统计与飞溅强度是关注通道，
派生电流比/功率比/单位电流能量等（与现有 73 维实现互相印证）。
拧紧示例预期：扭矩-目标偏差、上下裕度、双轴差、缺失标记（与现有 6 派生列互相印证）。

### S2 特征工程生成（LLM 写代码，沙箱执行）

- LLM 依据 `AnalysisReport.feature_engineering_brief` 生成**纯函数式特征脚本**
  （输入 DataFrame → 输出特征 DataFrame，禁 model/禁网络/禁全局状态，资源与超时受限），
  平台在**数据抽样（≤5k 行）上试运行**：可执行、无泄漏列、无全空列、行数保持。
- 失败自动回退：LLM 最多修复 2 次；仍失败则回退到**内置领域算子**
  （按 domain 选 `tighten_feature_engineering` / `spot_weld_features`）保证流程不断。
- 脚本与试运行指标（每列缺失率/方差）作为产物落盘，进入 S3。

### S3 自动建模（现有 AutoML，零改动）

- 输入：S2 特征数据集 + 目标列；搜索空间由 LLM 按画像微调
  （不平衡→class_weight、样本量小→缩 trials、时序漂移疑虑→按时间切分 CV）。
- 输出：Top-K（默认 3）候选的完整指标（CV AUC/F1/精度/召回 + feature_importance）。

### S4 评审验收（LLM 评审 + 硬门禁，双层）

**硬门禁（确定性，先跑，一票否决）**：
- 测试集（留出集）指标 ≥ 预设阈值：precision / recall / F1 / AUC
  （按业务分别设，如拧紧不合格召回 ≥ 0.90——漏检代价高）；
- 稳定性：Top-K 模型指标方差小（避免偶然冠军）；
- 泄漏复查：重要性 Top10 中不含 `leakage_suspects`。

**LLM 评审（软对齐，后跑）**——输入硬门禁结果 + feature_importance + S1 的
`expected_important_features`，输出 `ReviewVerdict`：

```json
{
  "verdict": "pass | fail | escalate",
  "alignment": {
    "TIGHTEN_LOWER_MARGIN": {"expected": "high", "observed_rank": 2, "consistent": true}
  },
  "surprises": ["ID(主键) 重要性排第 3，疑似索引泄漏"],
  "business_readiness": "不合格召回 0.93 达标；但 ID 特征主导建议下轮剔除",
  "next_iteration_hints": ["剔除 ID 列后重跑", "补充角度类特征（当前数据缺失）"],
  "confidence": 0.82
}
```

`fail` → 把 `next_iteration_hints` 写入迭代记忆回到 S1；`escalate` 或超轮次 → 人工介入。
**关键规则：LLM 只能建议，不能放宽硬门禁。**

### 固化：Pipeline Recipe（配方）

验收通过后，把整个过程固化为版本化 JSON（存全局模板体系，等价"智能建模配方"）：

```json
{
  "recipe_version": "tightening-v1.2",
  "inputs": {"target_column": "DECIDE(判定…)", "domain": "tightening"},
  "analysis_digest": "S1 报告摘要（供新数据 delta 分析用）",
  "feature_script": "<S2 定稿脚本（或内置算子引用）>",
  "automl_config": {"families": [...], "trials": 30, "cv": "stratified_5", "class_weight": true},
  "acceptance_gates": {"recall_bad": 0.90, "f1": 0.85, "max_importance_leakage": []},
  "review_log": ["轮1: fail-剔除ID", "轮2: pass"],
  "model_lineage": {"best_family": "hist_gradient_boosting", "test_metrics": {...}}
}
```

**复用方式**：
1. **回流重训**（现有闭环）：报错数据积累触发重训时按配方特征脚本+建模配置执行——
   LLM 不再全程参与，只有硬门禁失败时才唤醒 Agent 重新迭代（省 token、结果稳定）；
2. **新数据集**：LLM 只做 **delta 分析**（新画像 vs `analysis_digest`，差异小→直接按配方跑，
   差异大→进入完整迭代）；新产线换域（如超声波焊）→配方作为 few-shot 范例注入 S1。

## 四、人工介入点（仅三处）

| 介入点 | 时机 | 动作 |
|---|---|---|
| 目标列 + 硬指标确认 | 流程启动前 | 确认目标语义（0/1 方向！）与 precision/recall/F1 阈值 |
| 升级处理 | LLM `escalate` 或迭代超限 | 查看**全链路档案**（每轮报告/脚本/指标/评审）后决策 |
| 发布批准 | 验收通过后 | 批准配方固化与最优模型上线（复用现有注册-批准-换模链路） |

## 五、落地里程碑

| 阶段 | 内容 | 交付判据 |
|---|---|---|
| P1（1-2 周） | S1 数据画像工具 + AnalysisReport 契约 + LLM 调用封装（复用 chat 网关）；先在电焊/拧紧两个现有数据集离线跑通"分析报告"并与现有特征实现互证 | 两域报告的 focus_channels 与 expected_important_features 覆盖现有实现的核心派生列 |
| P2（2-3 周） | S2 脚本生成 + 沙箱试运行 + 回退；S4 硬门禁 + ReviewVerdict；Agent 编排循环（含迭代记忆） | 两域各完成一次"生成脚本 ≈ 内置算子效果"的端到端迭代（可强制一轮 fail 验证回环） |
| P3（1-2 周） | Recipe 固化 + 与回流重训集成（配方驱动重训）+ delta 复用；事件流与过程档案页面 | 拧紧回流数据按配方自动重训换模一次；新抽样数据 delta 复用跑通 |

## 六、主要风险与对策

| 风险 | 对策 |
|---|---|
| LLM 幻觉/脚本恶意 | 结构化契约 + 沙箱执行 + 资源限制 + 泄漏复查；LLM 永不直接执行，只产出被校验的产物 |
| 评估过拟合（迭代选型用了测试集） | 测试集只在 S4 出现一次；迭代选型用 CV；最终以留出集为准 |
| Token 成本 | 固化后默认走配方不唤醒 LLM；画像报告做列级摘要压缩；delta 复用 |
| 领域误判（把 ID 当信号） | S1 leakage_suspects 硬规则（索引/时间戳/单基数码列）+ S4 Top10 泄漏复查一票否决 |
| 不平衡数据学成全判多数 | 硬门禁按**少数类 recall** 设阈（拧紧不合格召回），不看 accuracy |

## 七、与两个现有闭环的整合图

```
电焊：原始报告(90列) ─┐                                  ┌─ 报错回流 ─→ 按配方重训 ─→ 换模
                      ├─→ [AutoML Agent 迭代] ─→ 配方固化 ─┤
拧紧：拧紧记录(20列) ─┘                                  └─ 新数据 delta 复用
（S2 参考基线：spot_weld_features 73维 / tighten 6派生列；S4 阈值：fault召回 / DECIDE不合格召回）
```
