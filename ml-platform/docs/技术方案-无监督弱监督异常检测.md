## 1. 背景与目标

### 1.1 问题定义

工业设备质量监控（点焊/拧紧）的现实数据约束：设备 99%+ 时间正常运行——正常样本海量且免费；故障样本稀缺且标注昂贵（需拆检/工单确认）。监督学习受制于此，固定阈值报警则误报率高（单指标正常波动被误判）。

无监督异常检测的价值主张（对齐汉云案例）：
1. **只用正常数据训练**（无目标列、无伪标签）
2. 学习**多维联合分布**——捕捉「每个单指标都在范围内、但指标组合关系异常」的隐性劣化（阈值法与监督法都覆盖不了的形态）
3. 输出离群分数 + 异常判定 + **逐特征归因**（现场可诊断）
4. **误报率较阈值基线下降 ≥30% 且已知真实异常不漏报**——本方案一切设计决策的服务对象

### 1.2 可行性结论（前期论证摘要）

- 平台已有弱监督聚类先例（UMAP+HDBSCAN，无目标训练/持久化/部署链验证过）
- 数据/特征/注册/部署/API 市场/编排/审计全链复用，缺口集中在引擎合同、评估体系、闭环漂移治理三处
- 闭环自动化（回流→重训→换模）恰好解决无监督模型最大工程风险「工况漂移→误报回升」——相对竞品的差异化优势
- 本方案为**引擎级真无监督**（非"自造目标列"捷径：训练全程无标签，评估用合成异常基准+运行期误报实证，contamination 进搜索空间，报警确认回流形成弱监督演进）

## 2. 总体架构决策：范式互斥与共享边界

**原则：范式在入口互斥、在合同镜像强制、随任务固化终身不改；基础设施全共享；两范式模型可在编排中协作。**

### 2.1 互斥层

| 层 | 规则 |
|---|---|
| 任务范式选择 | AutoML 新建 / 智能体向导第一步二选一：有监督（分类/回归/多目标）｜无监督（异常检测）。**创建后不可切换**（历史任务档案/配方/门禁按创建时范式解释；换范式=新建任务） |
| 引擎合同（服务端镜像强制） | 有监督：`target_columns` 必须非空（现状）；无监督：**必须为空**，传入即 422；无监督特征列必填（含全 NaN/常数列剔除），行数 ≥200 |
| 算法目录 | 家族×任务类型白名单（现有 `AlgorithmFamily.build` 校验机制）：iforest/ocsvm 仅注册在 anomaly，监督任务白名单天然不出现 |
| 智能体向导 | 范式随 `AgentRun.guidance` 固化 → S1-S5 按范式走分支 → 配方固化含范式，重放天然互斥 |
| 闭环配置 | 有监督：错误累计触发重训（error_classes）；无监督：分数漂移 PSI 触发重拟合（contamination/PSI 参数）。一个闭环任务只属一种范式 |

### 2.2 共享层（零分离，绝不重复建设）

项目、数据集与画像、特征清洗算子、工件存储（artifact 体系）、模型注册/ONNX/部署、API 市场、应用编排、平台审计、大屏。

### 2.3 合法并存场景

1. 同一数据集跑两种范式（监督 vs 无监督对比误报率的实验设计）
2. 编排混用：无监督检测器第一道筛（离群→报警）+ 下游监督模型定级定类（汉云式典型架构）
3. 弱监督演进：无监督任务积累确认标签后**派生**监督任务（带标签导出、预填特征），并存对比、达标后切换部署（保留无监督模型回退能力，不原地转换）

## 3. 技术方案

### 3.1 引擎：`anomaly_detection` 任务类型

**合同（`automl_search.py`）**

```
AutoMLContract(task_type="anomaly_detection",
               target_columns=[],            # 硬性为空，传入即 422（镜像互斥）
               input_columns=[...],          # 必填，全数值、无全 NaN/常数列
               contamination=0.01,           # 预期异常比例先验（向导可调）
               cross_validation_folds=0)     # 无常规 CV（合成基准替代）
```

改动点：`PERSISTED_TASK_TYPES` + `anomaly_detection`；`AutoMLContract.__post_init__` 无监督分支；`validate_target_columns` 旁路为特征数值性校验（复用 `_numeric_feature_columns` 语义）。

**执行分支（`automl_execution.py` 新 `_execute_anomaly_job`）**：与 multioutput 分支同型先例——多数据集合并、特征清洗、按族搜索、合成异常评估排序、冠军产出。

### 3.2 算法族与模型管线

| 族 ID | 管线 | 搜索空间 | 角色 |
|---|---|---|---|
| `iforest` | StandardScaler + IsolationForest | n_estimators ∈[100,400]、max_samples、contamination | 主力基线：快、稳、高维友好 |
| `ocsvm` | StandardScaler + OneClassSVM | nu ∈[0.01,0.2]、kernel(rbf/linear)、gamma | 小特征集高精度；>2 万行自动降采样（沿用 UMAP 路径既定策略） |
| `autoencoder`（二期） | torch 重构器，重构误差=分数 | hidden_dims、bottleneck 比例、epochs | 非线性联合分布 |

**管线强制结构（缺一不可用）：**

```
AnomalyPipeline = StandardScaler → {IF | OC-SVM | AE}
                → ScoreCalibrator    # 分数→[0,1]：训练期经验分位数标定（99 分位→阈值）
                → ThresholdPolicy    # 判定阈值 = contamination 分位数，随模型持久化
```

- Scaler 必须在 Pipeline 内（训练/推理/ONNX 一体，杜绝预处理漂移）
- **阈值随模型持久化**（非推理时重算）：换模对比、误报统计以「上线时标定阈值」为锚
- 产物：`anomaly_model.joblib`（Pipeline 整体）+ `score_stats.json`（训练期分数分位数表 = 漂移检测基线）
- 三族同台搜索、统一口径排序——AutoML 真实调参（Hyperband 资源机制天然兼容：iforest=n_estimators）

### 3.3 三层评估体系（方案核心——无监督可用性的分水岭）

**第一层：训练期合成异常注入基准（Synthetic Contamination Benchmark，排序依据）**

1. 训练集 80/20 分割：80% 拟合，20% 正常保留集
2. 保留集注入三类合成异常（覆盖工业异常典型形态）：
   - 均匀流形外点（完全偏离正常域）
   - 局部扰动点（±k·σ 高斯扰动——轻微劣化形态）
   - **单变量合理组合异常**（各单指标在 1.5×正常范围内、但取不合理组合——阈值法漏检、联合分布才能发现；降误报核心场景，必须专项注入）
3. 指标：
   - `synthetic_auc`（score 对合成异常 vs 正常保留集）——主排序键
   - `perturbation_recall`（最难形态敏感度）——次排序键
   - `normal_fpr`（保留集误报率，应 ≈ contamination）——自洽性校验
4. **稳定性校验**：子采样 5 次重训，分数 Spearman ≥0.8 才可为冠军（无监督不稳定=上线误报失控头号原因）

**第二层：验收期（S4 证据面板）**
- 离群分数分布直方图（双峰性可视化）
- 注入强度-检出率曲线
- 可选弱监督验证：用户提供少量真实异常（≥10 条）→ precision@k + 已知异常召回
- 验收门禁键（`acceptance_gates` 新任务类型默认门禁，与监督 recall_minority 并列）：
  `synthetic_auc ≥ 0.85`、`normal_fpr ≤ contamination×1.5`、`stability ≥ 0.8`

**第三层：运行期误报实证（最终验收）**
- 闭环监控：同期**阈值报警数 vs 异常检测报警数**对比曲线
- 报警确认回填统计（真/误报）——「FPR 下降 ≥30%」以这里的数据说话

### 3.4 智能体向导适配（S1-S5）

| 阶段 | 改动 |
|---|---|
| 向导第一步 | 任务类型增「异常检测（无监督）」；选中后**目标列控件整体隐藏**（非置灰），出现 contamination 参数（默认 1%，文案：宁低勿高）|
| S1 分析 | 无监督分支提示词：识别疑似泄漏列（数据混有结果标签列时提示剔除——正常数据训练最忌标签泄漏进特征）；正常性画像（分布形态/量纲差异）|
| S2 特征 | 照常 + 无监督专项：剔除常数/近常数列（零方差特征毒害距离模型）、强共线列合并提示 |
| S3 训练 | 三族搜索 + 合成基准排序；产物 `anomaly_model.joblib` |
| S4 验收 | 3.3 第二层证据面板 + 门禁；可选上传少量已知异常样本弱监督验证 |
| S5 服务化 | 部署输出合同见 3.5 |

合同层：`AgentRunCreate.target_column` 放宽可空（`agent_center.py` `min_length=1` → 可空）；runner 三处目标列引用（S1 提示词 :254 / S3 目标值 :383 / S4 评估 :768）加空值护栏走无监督分支。

### 3.5 服务化部署与可解释性

- **ONNX**：skl2onnx 对 `Pipeline(Scaler, IsolationForest)` 与 `Pipeline(Scaler, OneClassSVM)` 原生支持；`onnx_worker` 家族登记处补注册（MLP 补登记先例）；OC-SVM float32 输入敏感性**必须实测**；输出 `score + label` 双端口
- **推理响应合同**：
  ```json
  {"anomaly_score": 0.93, "is_anomaly": true,
   "top_contributors": [{"feature": "wld1c", "contribution": 0.41}, ...]}
  ```
- **top_contributors 逐特征归因（工程必备）**：IF=路径深度差分；OC-SVM=对偶系数/特征梯度；AE=逐特征重构误差分解——现场工程师要「哪个参数异常」，不只「异常」

### 3.6 闭环：漂移治理与弱监督反馈（无监督上线后持续可用的关键）

**漂移治理链（重定义无监督的「回流→换模」语义）：**
1. 回流：推理数据照常回流（回流行=特征+分数+判定，无标签要求）
2. **漂移检测（新增自动）**：回流分数分布 PSI（对 `score_stats.json` 基线）——PSI>0.25 触发重拟合预警。分数分布漂移比单特征漂移**更早**发现模型失配（先于误报显性化）
3. 重拟合（换模）：近 N 天回流数据、**「仅正常数据」策略**（剔除高分样本后拟合——防把缓变故障学进正常包络）→ 同一 AutoML 合同 → 换模门禁=新模型对基线期已知报警样本分数不下降（防重拟合洗掉历史检出能力）
4. 误报反馈闭环（**弱监督核心机制**）：报警面板每条可标记「确认故障/误报」
   - 误报样本 → 排除集 → 下次重拟合降权/剔除该区域（收窄误包容）
   - 确认故障 → 验证集 → precision@k 评估 + 未来半监督精调标签库
   - 即「标注从工单回流」，与现有回流架构同构，标注成本≈0

**分工况建模**：向导暴露可选「工况列」——指定后按工况值自动切分数据集分别建模、部署多模型路由（复用现有多模型路由机制）；不指定则全量单模型。一期即做（工况混杂数据上线第一天误报率就不可控）。

### 3.7 数据与迁移

- **零新表**；`PERSISTED_TASK_TYPES` 为引擎常量非库表
- 工件：`anomaly_model.joblib` + `score_stats.json` 走现有 artifact 体系
- 回流确认标记：回流数据集追加 `feedback` 列（confirmed_fault/false_alarm，可空）——回流数据集动态生成，加列即生效，无迁移
- 配方固化：content 增 `anomaly: {method, contamination, condition_column}` 段，重放走同一合同

### 4.2 一期总验收（真实可用的判据，M1-M4 完成后）

2. API 返回 score / is_anomaly / top_contributors 三要素

## 5. 方案边界（明确不做）

- 不做「自造目标列」伪无监督捷径（已论证否决：AUC 对伪标签无意义、contamination 不可调、无漂移治理）
- 不做原地范式切换（监督↔无监督任务互转）
- 不做视频/PDF 输入的异常检测（输入模态与任务正交，按现有 input_types 机制走）
- 三期前不做跨设备迁移与机群统一基线

### 6.0 一期实测数据对二期设计的输入

| 一期事实 | 对二期的影响 |
|---|---|
| ocsvm combinatorial 检出 **0.79**（三类中最弱，真实拧紧数据） | AE 的核心价值论证点：重构误差对「密度空洞组合异常」的捕捉可能优于轴平行切分模型——二期 AE 以 comb 检出率为首要对照指标 |
| 真实数据 iforest AUC 0.961 / ocsvm 0.993 全门禁过 | AE 边际收益有限的风险——以「comb 检出率 +1σ 或单形态冠军」作为立项门槛 |
| ONNX `scores` 端口=decision_function（正=正常），推理侧取负统一 | AE 输出合同必须对齐「越高越异常」统一口径（负重构误差），方向**必须实测**（M3 坑①） |
| ai.onnx.ml opset 封顶 3（skl2onnx 链） | AE 走 `torch.onnx.export` 独立路径，不受此限，但 ORT 1.24.4 载入+一致性需独立实测 |
| 归因=中心差分数值梯度（`automl_anomaly.anomaly_top_contributors`，通用三族） | AE 复用中心差分即可；逐特征重构误差分解作为可选增强（更精准但新增实现） |
| `WeightedTargetRouter`=纯权重灰度（测试锁死） | 工况分片路由必须**新 Router**，不改造现有（灰度场景保留） |
| PSI 基线=score_stats 201 点分位表 | AE 产物只要同格式 score_stats，漂移链零改动接入 |

### 6.1 二-1：autoencoder 算法族

**管线**（对齐一期强制结构 `Imputer→Scaler→检测器`）：

```
AnomalyPipeline(AE) = Imputer → StandardScaler → TorchAutoencoder(封装 decision_function/predict)
                    → ScoreCalibrator(重构误差分位数标定) → ThresholdPolicy
```

**关键设计：sklearn 兼容包装**——`TorchAutoencoder` 实现合成基准与评估器所需的 `decision_function`（=负重构误差）/`predict`/`score_samples` 接口，使 automl_anomaly.py 的合成基准/标定器/稳定性校验/归因中心差分**零改动复用**；注册进 `ANOMALY_PIPELINE_DETECTORS`（onnx_worker 二期位已留）与目录（`supported_tasks=("anomaly_detection",)`）。

**搜索空间**：bottleneck 比例 ∈{0.1, 0.25, 0.5}、隐藏层数 ∈{1,2,3}、epochs（resource_parameter，Hyperband 兼容）、learning_rate ∈{1e-3,1e-4}；训练协议：保留集重构损失早停 + 去噪正则（输入加 σ=0.05 噪声，denoising AE 提升正常包络平滑性）。

**先决验证项（M5-0，动实现前必做）**：
1. torch.onnx.export 对封装模型的导出 + ORT 1.24.4 载入 + scores 方向实测（M3 坑①教训：不猜方向）
2. joblib vs ONNX 重构误差一致性容差断言（CPU 确定性：`torch.set_num_threads(1)` + 固定种子）
3. stability_check 成本实测：5 次 80% 子采样重训 × epochs——超预算则 AE 的 stability 改为「同模型双次推理确定性」+ 缩减 epochs 上限

**验收**：合成基准三指标与双族同门禁；**comb 检出率 ≥ ocsvm 基线（0.79）+0.05** 才采纳为可选族，否则如实记录「AE 在本域无边际收益」并保留族位（数据说话原则）。

**工作量**：约 600-800 行（模型封装+注册+ONNX 路径+测试三件套）。

### 6.2 二-2：半监督精调（报警确认标签的三个消费档）

一期 M4 已交付标签基础设施（feedback_marks 列 + confirmed_fault/false_alarm 标记 API/面板 + 仅正常重拟合排除集消费）。二期在此之上建「精调」层：

**前置门槛（不满足则本项自动顺延）**：confirmed_fault ≥50 条且覆盖 ≥2 种异常形态（判定：标签库按形态聚类粗分）。

| 档 | 方法 | 改动面 | 风险 |
|---|---|---|---|
| 档 1（默认） | **标签阈值重标定**：confirmed_fault 分数分布 + false_alarm 分数分布 → 最小化加权损失（漏报罚 2×误报）求最优阈值，替换 ThresholdPolicy.persisted | 只改 score_stats 产物+标定器一个函数；ONNX 零重训（阈值在推理侧应用） | 最低 |
| 档 2 | **校准层替换**：冻结 score 上训 isotonic 回归（score→故障概率），替换 ScoreCalibrator | 管线尾部替换；**ONNX 需再导出再验证**（skl2onnx isotonic 支持） | 中 |
| 档 3 | 成本敏感弱监督重训 | 大改，暂缓（标签 ≥500 条再评估） | 高 |

**硬约束（一期方案已定）**：只动校准/阈值，**不动特征表示与检测器主体**——防正常包络失去锚点。

**验收**：precision@k（k=报警预算）较一期标定提升；**合成基准重跑必须仍全过门禁**（防精调过拟合确认样本）；false_alarm 样本分数分布显著下移。

**附加产出：误报形态分析报表**——false_alarm 样本在特征空间的聚类画像（哪些参数区域误报密集）→ 反哺用户调 contamination/特征工程（人机协同闭环，汉云「AI+机理+专家知识库」的对应物）。

**工作量**：约 400-500 行。

### 6.3 二-3：部署路由拓扑（工况分片，一期最大遗留）

一期 M4 把 `condition_column` 打通到合同链（guidance→配方→重训参数），**部署路由明确留二期**（M4 台账：现 WeightedTargetRouter 纯权重灰度测试锁死，特征值路由需新 Router）。

**设计**：

1. **新 `ConditionValueRouter`**（inference_rollout.py 新类，不动 WeightedTargetRouter）：
   - 匹配语义：DeploymentTarget 增 `condition_value` 字段（迁移 99，nullable=通配）；请求记录按 `condition_column` 列取值 → 精确匹配 target；未命中 → **默认分片**（训练量最大的分片）+ `unknown_condition` 事件
   - condition_column 来源链：部署→版本→training_job.condition_column（**一期实际未落库此键**——M4 只打通 guidance→配方→重训 hints，trigger_retrain_job 的 params 无 condition_column；二期先补「配方/向导 → 重训参数」链路，再接路由）
2. **多分片产出链**（引擎侧新增分组训练）：anomaly 任务带 condition_column → 按工况值分组 → 每组独立跑 M1 合成基准全流程 → N 个 bundle（各自 score_stats/threshold）→ 注册 N 版本挂同一部署的 N targets（condition_value 标注）
   - 分组最小行数护栏（每组 ≥200，不足并入 default 组并留痕）
3. **漂移与反馈按分片独立**：PSI 基线/重拟合/换模门禁（detection_retention）全部 per-shard——分片共享检测器主体语义但标定独立，与三期「per-device calibration」同构（三期是其规模化）
4. **推理合同不变**：三要素输出（分片选择对调用方透明）；响应可选增 `condition_value` 回显（排障用）

**验收**：双工况合成数据→分组训练→部署→按工况路由各归其模（交叉注入验证：A 工况异常在 B 分片下分数显著不同）；unknown_condition 兜底事件落审计；存量纯灰度部署路由行为零变化（回归锁）。

**工作量**：约 600-700 行（二期最大块）。

### 6.6 二期方案审核补充（2026-11-12 一期落地后复审，3 个接口偏差 + 2 个实现补充）

> 对 §6.0-§6.5 以一期实际代码逐条复审后的修正与补充，开工前必读。

**A. 推理判定口径与 ThresholdPolicy 脱节（一期隐性不一致，二-2 的前置修正）**
一期 ONNX 推理路径的 `is_anomaly` 判定来自 ONNX 图的 **label 端口**（sklearn `predict` 的 offset 语义，contamination="auto"），**不是** `score_stats.threshold_score`——`threshold_policy` 随模型持久化了但推理判定未消费它（`inference_deployment.anomaly_predict_enrichment` 只做分数取负+label 映射）。后果与修正：
- 二-2 档 1（标签阈值重标定）的生效前提是「阈值在推理侧应用」——当前不成立，需先把 enrich 的 `is_anomaly` 判定统一改为 `anomaly_score ≥ threshold_score`（从 bundle/threshold_policy 取，随版本下发），ONNX label 端口仅作参考输出
- 该统一同时消除一期隐性口径分歧：label 端口（offset 语义）与 threshold_policy（保留集分位）两套阈值并存，重标定只改前者会不生效

**B. `pipeline_anomaly_scores` 属性分派顺序与 AE 接口设计的冲突**
`automl_anomaly.pipeline_anomaly_scores` 的分派顺序是 `score_samples` 先于 `decision_function`（IF 语义）。§6.1 让 `TorchAutoencoder` 同时实现三个接口——若 AE 也实现 `score_samples`，会先命中 score_samples 分支再取负，**方向语义取决于 AE 的 score_samples 定义**，重蹈 M3 坑①（不猜方向）。修正：AE 接口约束为**只实现 `decision_function`（=负重构误差，越高越异常）与 `predict`，不实现 `score_samples`**；并在 M5-0 先决实测中加「AE 分数方向断言」（正常样本分数 < 已知异常样本分数）。

**C. AE 必须实现 sklearn clone 协议**
`stability_check` 用 `clone(fitted_estimator)` 做子采样重训——`TorchAutoencoder` 需继承 `sklearn.base.BaseEstimator` 并实现 `get_params/set_params`（构造参数全部显式保存），否则 clone 抛错导致 stability 恒 0（门禁必挂）。M5 先决验证加一条。

**D. AE 单 trial 训练成本对搜索预算的冲击（M5 先决补第 4 项）**
合成基准评估每个 trial 都要完整训练 AE（epochs×数据量），成本比 IF/OC-SVM 高一个量级。M5 先决实测「单 trial 训练时长」→ 据此决定：AE 只在 high/ultra 搜索强度出场，或 AE 参与时双族 trial 数减半；超预算则 AE 降级为「独立任务类型外挂」不进同台搜索。

**E. 分组行数护栏数字统一**
§6.3 分组护栏 ≥200 行；一期 anomaly_trainer 分段要求 ≥60（_train_single 下限 40）——二期 M7 实现时统一为 ≥200（与 M1 fpr 统计容差的 Binomial 教训一致），避免小样本分片的 fpr 门禁随机挂。

## 7. 三期详细方案（机群规模化：统一基线与跨设备迁移，2026-11-12 增补）

> 三期的两个能力本质是同一个机制的两次应用：**per-device calibration（设备级标定）**——检测器主体（正常包络的联合分布）跨设备共享，标定/阈值按设备独立。一期 M1 的「模型主体与标定分离」架构（anomaly_model.joblib + score_stats.json 双工件）天然为此预留。

### 7.1 三-1：机群统一基线（多设备联合训练 + 设备级标定）

**问题定义**：多台同型设备各自独立建模 → 每台都要 ≥1 万行正常数据且各自维护，成本高且新设备无冷启动能力；直接混训 → 设备个体偏差（传感器基线差异/装配离散）被当成异常，误报率不可控。

**方案：全局模型 + 设备级标定（分层建模的轻量实现）**

1. **全局模型**：多设备数据联合训练（多数据集合并训练已具备）——检测器主体学习「同型设备共有的正常联合分布」；设备 ID 列必须从特征中剔除（S1 泄漏列提示已有此能力，机群场景显式化）
2. **设备级标定**：每台设备用本设备正常数据（≥200 行）独立跑 ScoreCalibrator + ThresholdPolicy → per-device score_stats/threshold
   - 原理：设备间差异主要表现为分数分布的整体平移/伸缩（传感器基线），联合分布的**形态**是共有的——分位数标定恰好只吸收平移/伸缩
   - 判据：设备级标定后 normal_fpr 回到 contamination 邻域（若某设备标定后仍超 1.5×，说明该设备分布形态异于机群——如实标记「不适配机群基线」，独立建模）
3. **数据组织**：device_id 作为 condition_column 的一等应用（二期分片路由的消费端）；多设备联合训练任务 = 多数据集合并（已有）+ condition_column=device_id
4. **部署形态**：一个部署 + N 设备分片（复用二期 ConditionValueRouter）——机群基线在部署面就是「工况分片」的 device 维特例

**验收**：≥3 台同型设备真实数据——机群基线+设备级标定的误报率 ≤ 各设备独立建模基线×1.2（机群化不得显著劣化）；单设备新数据标定后 fpr 回落实测。

**工作量**：约 500 行（分组训练复用二期 M7 分片链 + 设备级标定调度）。

### 7.2 三-2：跨设备正常包络迁移（新设备冷启动）

**问题定义**：新装同型设备没有历史数据，独立建模需等待数月正常数据积累。

**方案：机群基线 + 新设备短期数据重标定**

1. 新设备接入 → 采集 1-2 天正常数据（≥200 行）→ **只重跑 ScoreCalibrator/ThresholdPolicy**（不动全局检测器主体）
2. 迁移有效性回测：若新设备有历史已知异常（调试/验收期人为注入或首月确认报警）→ 按一期合成基准口径回测检出；无异常样本则回测合成基准在该设备数据上的 AUC
3. **不适配护栏**：标定后 normal_fpr 超 1.5×contamination → 判定该设备分布形态异于机群（传感器型号差异/工况特殊）→ 自动降级为「独立建模任务建议」+ 提示采集更多数据；**不硬迁**
4. 演进：新设备数据积累达标后（≥1 万行）→ 一期标准流程独立建模 → 与迁移模型并存对比 → 达标切换

**验收**：同型新设备（或既有数据中留出一台模拟新设备）——迁移模型标定后 fpr 达标 + 留出异常回测检出 ≥ 独立建模基线×0.9。

**工作量**：约 300 行（核心是 7.1 标定机制的复用 + 回测脚本 + 不适配降级流）。

### 7.3 三期里程碑与排序

| 片 | 内容 | 估算 | 依赖 |
|---|---|---|---|
| M8 | 设备级标定调度 + 机群联合训练任务形态 | 300 行 | 二期 M7 路由 |
| M9 | 新设备迁移流 + 回测 + 不适配降级 | 300 行 | M8 |
| M10 | 机群监控视图（per-device fpr/PSI 聚合大屏） | 200 行 | M8 |

三期总量约 800 行——显著小于一二期的原因：机制本体（标定/模型分离、分片路由、PSI）在一二期全部就位，三期是组织方式的规模化。

### 7.4 三期前置条件

- 二期 M7（分片路由）上线且经真实多工况数据验证
- ≥3 台同型设备的同构特征数据（特征列集合一致——不同批次设备特征演化需先做特征对齐，这是三期最大的隐性前置，建议三期开工前用一期 S1 画像能力做特征集 diff）
- 机群至少一台设备的确认报警样本（detection_retention 机群版门禁的数据基础）

### 7.5 三期风险与预案

| 风险 | 预案 |
|---|---|
| 设备间分布**形态**差异（非平移）导致机群基线误报失控 | 设备级标定后 fpr 校验不过即自动标记「不适配」降级独立建模——机制上不可能硬迁 |
| 特征集漂移（不同批次设备列不一致） | 三期开工前特征集 diff 前置；不一致列集的设备不进同一基线 |
| 分层后 detection_retention 门禁的跨设备语义 | 确认报警样本按设备归属分片校验（每分片独立 retention，不跨片） |
