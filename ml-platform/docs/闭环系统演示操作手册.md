# 闭环自动化系统 演示流程说明

> 更新：2026-10-10。对齐当前系统（列表/详情分页、配置弹窗、多数据集合并重训、单一审核任务、大屏任务选择）。
> 演示账号：admin / admin123 · 主平台：http://localhost:5173 · 后端：8001

## 系统组成

| 页面 | 地址（导航入口） | 角色 |
|---|---|---|
| 自动化闭环 | `/demo-loop`（导航「闭环自动化」） | 任务列表：新建/编辑/删除闭环任务 |
| 闭环任务详情 | `/demo-loop/{任务ID}`（列表点行进入） | 逐行推理 + 闭环状态，单任务专属 |
| 应用编排 | `/orchestration` | 服务图编排 → 发布为 API |
| API 市场 | `/api-marketplace` | 编排 API 管理（调用/测试/下线/删除） |
| 运行监控大屏 | `/demo-showcase.html` | 可视化大屏（模拟/实时双模式） |

**全链路一句话**：上传 CSV → 逐行真实推理 → 报错行回流该任务专属数据集 → 阈值告警（站内通知）→ 人工审核（每任务同一时间仅一个标注任务）→ 报错积累触发自动重训（多数据集合并 + 回流数据自动打标签）→ 最优模型自动替换部署。

## 二、方案 A：自动化闭环（核心演示，约 8 分钟）

### 2.1 新建闭环任务（列表页 → 弹窗）

1. 导航「**闭环自动化**」→ 选项目（test112）→ 右上「**新建闭环**」；
2. 弹窗中按下表填写后点「**创建闭环**」：

| 配置项 | 演示建议值 | 说明 |
|---|---|---|
| 闭环名称 | 自动化闭环 | 同项目重名会**自动改名**为 ××-2，不报错 |
| 推理部署 | 自动化测试 | 逐行预测走它的真实模型 |
| 报错类别 | 1 | 预测=1 判定为报错行 |
| 告警阈值 | 2 | 每 2 行报错触发一次管理员告警 |
| 自动特征工程 | 开 | 原始报告行自动补齐 73 特征 |
| 人工审核 | 开 | 告警自动创建标注任务并分配标注员 |
| 审核标注员 | jing | 告警后自动分配 |
| 自动重训 | 开 | 报错积累触发 AutoML |
| 重训触发行数 | 3 | 报错积累 3 行触发建模 |
| 重训数据集 | **labeled_fea.csv + 任务名-报错数据**（多选） | 多个数据集合并训练；报错数据无标签列时自动用**推理结果**补齐为 fault 标签 |
| 重训目标列 | fault | 分类目标 |
| 搜索试验次数 | 5 | 越大越慢越优（5 约 90 秒） |

### 2.2 进入任务详情页

列表**点击任务行**（或行内「详情」）→ 详情页顶部有：返回列表 / 任务名 / **编辑配置**（弹窗修改）/ 刷新 / 运行监控大屏 / **重置闭环**。
「逐行推理调用」「闭环状态」两张卡只在详情页显示，标题带任务名——**所见即该任务**，多任务不混淆。

### 2.3 启动闭环（全流程真实运行）

1. 「逐行推理调用」卡：**上传 CSV** → 选 `labeled_features_demo.csv`；
2. 点「**启动闭环**」→ 页面逐行真实调用推理 API：
   - 每行显示预测类别 + 置信度，报错行标红「已回流」；
   - 报错行**自动追加到该任务专属的「任务名-报错数据」文件**（含 fault=预测值标签）；
   - 每达告警阈值 → 管理员告警 + 站内通知（右上角铃铛）；
   - 报错积累到重训阈值 → **自动触发 AutoML**（约 90 秒）→ 完成后**自动换模型**，事件流金色提示「推理模型已替换」。

### 2.4 六个环节在哪看

| 环节 | 详情页演示时看 | 事后查 |
|---|---|---|
| ① 逐行预测 | 行卡片（类别/置信度）+ 状态卡「已推理」计数 | 模型库 → 部署调用监控 |
| ② 错误回流 | 红色「已回流」标记 | 数据管理 → 任务名-报错数据 行数增长 |
| ③ 阈值告警 | 告警横幅（脉冲）+「告警次数」 | 右上角铃铛 → 站内通知（列表可滚动） |
| ④ 人工审核 | 事件流「已创建人工审核任务」 | 数据标注 → 任务名-人工审核-N；jing 登录门户处理 |
| ⑤ 自动重训 | 事件流「自动建模任务已触发」→「执行中」 | 状态卡「自动建模」徽标；自动建模页看任务 |
| ⑥ 模型替换 | 事件流金色「推理模型已替换」+ 模型卡翻转动画 | 模型库 → 部署指向新模型版本（可回退） |

### 2.5 关键规则（演示可讲的设计点）

- **报错数据单文件追加**：每个任务的报错数据持续追加到它自己的一个文件，不新建文件、不跨任务混写；
- **单一审核任务**：每任务同一时间只有**一个进行中**的审核任务——审核未完成时新报错继续累积（事件流提示"任务仍在进行中"），任务完成后下一轮告警才建新的；
- **多数据集合并重训**：所选数据集按选择顺序合并为「合并数据集」训练；**注意所选数据集列体系要一致**（本手册演示 CSV 与 labeled_fea.csv 同为 73 特征列体系）；
- **回流数据自动打标签**：回流行落盘自带 fault=预测类别，历史无标签回流文件在合并时用 prediction 列补齐。

### 2.6 重置

详情页「**重置闭环**」：清空计数/事件/换模水印（配置与报错数据文件保留）。演示第二轮前建议先重置。

## 三、运行监控大屏（收尾，约 3 分钟）

地址：**http://localhost:5173/demo-showcase.html**（新标签页）

### 模拟模式（开场暖场）

默认播放：星空场景粒子流动、报错红色回流、告警铃铛、重训进度环充满自动换模型（v1→v2 金色弧线）。控件：播放/暂停/重置/×1×2×4 倍速。

### 实时模式（接入真实数据）

1. 左下角「模式：模拟」→ 切「模式：实时」；
2. 依次选 **项目 → 闭环任务**（两个下拉）→「**连接**」；
3. 顶部指标为真实计数（100ms 轮询）：
   - **已推理** = 已推理的数据**条数**（非 API 调用次数）
   - **正常通过** = 未报错的数据条数（已推理 − 回流）
   - 报错回流 / 管理员告警 / 线上模型版本同步显示；
4. 配合闭环详情页「启动闭环」，观众看到真实数据实时驱动大屏动画（新事件触发粒子/告警/换模特效；连接瞬间只同步计数不回放历史）。

## 四、方案 B：应用编排 → API 市场（约 8 分钟）

### 4.1 新建服务图

导航「**应用编排**」→ 选项目 →「**新建编排**」→ 填名称（如"焊接质量推理服务"）→ 自动进画布。

### 4.2 搭建全闭环服务图（拖拽连线）

| 算子（面板分类） | 作用 | 关键参数 |
|---|---|---|
| API 输入（数据输入输出） | 接收逐行调用 | 无 |
| 加载模型制品（传统机器学习） | 绑定已训练模型 | model_artifact_id |
| 应用模型（传统机器学习） | 推理 | 模型口接「加载模型制品」 |
| 条件分支（流程控制） | 分类判断 | column=prediction，等于报错类别 |
| 追加报错数据集（数据输入输出） | 报错行回流 | dataset_artifact_id |
| 通知管理员（数据输入输出） | 站内告警 | title/message |
| 重训阈值判断（流程控制） | 积累判断并触发重训/换模 | 重训数据集/目标列/阈值/swap_deployment_id |

连线：API 输入 → 应用模型（data）；加载模型制品 → 应用模型（model）；应用模型 → 条件分支；**true 分支** → 追加报错数据集 → 通知管理员 → 重训阈值判断；false 分支即正常行出口。

> ⚠️ 发布门禁：服务图必须含 API 输入 + 应用模型，**禁止训练/搜索算子**（模型经「加载模型制品」冻结绑定，训练与服务分离）。

### 4.3 发布与调用

1. 画布顶部「**发布为 API**」→ 保存 → 发布版本 → 注册编排 API（门禁不过时 toast 说明原因）；
2. 导航「**API 市场**」→「Orch. API」筛选：详情 / 测试 / 下线（暂停）/ **删除**；Calls 与 Success Rate 实时累计；
3. 程序化逐行调用：
   ```
   POST /api/platform/apis/orchestration/{版本ID}/invoke
   Authorization: Bearer {token}
   {"record": { ...单行特征... }}
   → {"records": [...], "branch": "true|false"}
   ```
4. 模型 API（部署自动发布）在市场**无删除按钮**——生命周期归模型库（删部署时市场行自动清理）。

## 六、常见问题与排除

| 现象 | 原因 | 处理 |
|---|---|---|
| 列表显示"暂无闭环任务" | 任务被删除（用户操作） | 「新建闭环」重建即可（报错数据文件保留） |
| 页面没有新功能 | 浏览器缓存旧版 | Ctrl+F5 强刷（服务端已强制 no-cache，一般无需） |
| DEMO_LOOP_RECORD_INVALID 缺特征列 | CSV 缺模型特征列 | 开自动特征工程并含波形列，或用 73 特征体系 CSV |
| 重训报"数值特征不足 10 行" | 所选数据集与回流行**列体系不一致**（交集列太少） | 重训数据集与演示 CSV 选同一体系（如 labeled_fea.csv） |
| 重训报"目标列 fault 不在数据集中" | 旧版行为（已修复） | 现报错数据自动带标签；仍报错请确认目标列拼写 |
| 部署删除后市场仍显示 | 旧版孤儿行（已修复） | 现删除部署自动清理市场行 |
| 审核任务一直不新建 | 设计行为：进行中的任务不重复创建 | 完成当前任务后下一轮告警自动再建 |
| 模型制品文件缺失 | 存储卷曾被重建 | 报错数据集自动自愈；模型重训或指回完好版本 |
| 全部容器消失 | WSL 空闲关停 | `docker compose up -d` 恢复（数据在命名卷） |
| localhost 打不开但 WSL 内正常 | localhost 转发失效 | `wsl --shutdown` 后重启栈 |
| CORS_ORIGIN_FORBIDDEN | 用了 127.0.0.1 访问 | 改用 http://localhost:5173 |
