### 5.2 P1：功能缺口

- 选样 API 用的是**假 bundle**：从客户端每行的 `probability` 拼 `[1-p, p]`（`api/label_quality.py:113-123`），不加载模型，`model_version_id=None`。选样结果没有任何消费方（不能接入标注任务）。
- `boundary` 是按簇内行序切 `[25%, 25%+配额)`，与到簇中心距离无关；三类视图同样按行序切三段，不读簇中心（原文 §3 已登记「簇内序次近似」）。
- hybrid 不支持 boundary / rarity / business_priority。
- κ 只算硬编码的 `"label"` 键，「多列按列算」未实现。
- **盲标 `subject_id` 来自请求体，不绑定当前用户**（`api/label_quality.py:57-62, 229-247`），一人可替所有标注位提交。
- 伪标签：红线因「没有任何训练或评估路径消费 `pseudo_label_batches`」而空洞成立；API 硬编码 `labeled_counts={}` 使每类配额退化为恒 1；`compare_on_dev_validation` 无 API 端点，winner 恒为 0。

### 5.3 P2：前端

选样 / Kappa 仲裁 / 伪标签在数据标注页的承载**完全未落地**（计划 §10）。原文「UI 随 M2 补」，M2 已收口而未补。
