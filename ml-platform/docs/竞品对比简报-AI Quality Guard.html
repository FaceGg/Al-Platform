十、确认的优势与弱点

优势（不可轻敌的部分）

  1. 质量域机制完整度业内少见：SPC（Nelson 1-8 + 能力指数）、8D/NCR/CAPA/SCAR/控制计划/MSA、预警处置、证据链打包（SHA-256）一应俱全，且细节口径诚实（Cp 用组内标准差、Ppk 用整体标准差等均有脚注）。
  2. 漂移监控是实测中唯一自动运转的能力：定时批检真实产出严重级报告（PSI 4.454），指标口径（PSI / PCA 重构误差 99 分位 / DQ 硬失败）教科书级严谨。
  3. 「诚实设计」抬升可信度：数据陈旧自曝横幅、风险分口径脚注、空态引导文案、审批过期自动回收、影子模式注明「只输出一致率」——面向审核者的产品语言做得到位。
  4. 低资源 + 边缘是真实成本优势：2C/1.9G 不依赖 Redis（数据库队列+原子抢占）；边缘版单盒已注册运行（ONNX 包 + 设备影子 desired/reported + 心跳），适配无 GPU 车间机房。
  5. 标签治理设计有想法：整簇标注门槛（纯度≥0.8 且样本≥10）、Kappa 一致性 + 仲裁、弱监督仅作建议——理念正确，只差运营验证。

弱点与风险

  1. 闭环无人运转：预警、标注、审批三个「人」的环节全部停滞（超时/等待/过期），产品卖的是框架而非运营验证。
  2. 技术底座薄弱且路线受限：无工作流编排、AutoML 仅固定分类器下拉（无超参搜索/实验追踪）、智能体为规则型（模板问答 + MCP 工具调用），无 LLM 深度应用；前端无构建静态站，长期可维护性与交互上限低。
  3. 实时能力未验证：实时链路停留在功能存在层面，本实例从未启动过。
  4. 验证与门禁的实际成色：F1 0.999 的浅验证集放行、DOE 作用于 ID 列，说明「严谨机制」之下工程判断仍有明显漏洞。
  5. 质量体系长尾是空壳：NCR/SCAR/控制计划/知识库均为 0 记录——这些模块是投标 checkbox，缺乏真实业务流量打磨。
