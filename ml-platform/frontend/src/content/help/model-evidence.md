# 模型库 · 闭环证据总览（算法平台 · 模型库）

在「模型库」里打开某个模型的版本列表，每个版本旁有「证据总览」入口。它回答的是审厂时最常被问的一句话：**这个模型版本从数据到上线，每一步的依据在哪里。**

## 闭环 12 环节

接入 → 切分 → 智能分群 → 人工标注 → 主动选样 → 训练 → 评估 → 发布上线 → 推送生产 → 现场验证 → 问题反馈 → 迭代优化。

每个环节有一个状态和可下钻的依据记录：

| 状态 | 含义 |
|---|---|
| 完成 | 该环节的记录存在，可直接打开 |
| 待发生 | 该环节尚未发生（例如还没有部署到生产） |
| 缺失 | 应当存在的记录找不到——需要排查 |
| 未接入 | **平台当前版本还不产出这类证据**，不代表该模型有问题 |
| 不适用 | 对该模型不适用（如外部导入模型没有平台训练记录） |

「未接入」的三个环节会随后续批次补上：切分与主动选样随第二批接入，现场验证随第四批（盒端回执）接入。在这之前，页面如实标注而不是显示成「缺失」或「完成」。

依据记录旁有「打开」按钮的可直接跳到对应页面（数据管理、数据标注、训练任务、模型库、闭环演示）；没有对应页面的依据只展示引用编号。

## 上线检查五项

- **模型文件**：模型工件存在且未归档；
- **校验和**：模型工件登记了 SHA-256。总览页只检查「是否已登记」，不重算文件哈希；
- **数据版本**：能追溯到就绪的数据集版本；
- **评估完整性**：有数值型评估指标；
- **生产版本唯一**：同一模型下只有一个版本处于生产运行态。

## 留档

「留档本次检查」会**重新读取模型文件计算 SHA-256 并与登记值比对**，同时把当时的 12 环节快照一并存档。文件被改动过会直接报未通过。留档需要项目管理权限（项目负责人或编辑者）。

## 导出证据包

「导出证据包」生成一个 ZIP：模型版本与 12 环节、上线检查、训练任务、数据集版本、部署、相关预警，以及模型文件本体（不超过 64MB；超过时只放元数据与校验和并在包内写明）。包内附 `MANIFEST.SHA256`，拿到另一台机器上执行 `sha256sum -c MANIFEST.SHA256` 即可逐个校验。

审计日志只在导出人持有审计查看权限时随包。预警处置单也可以从处置流程导出证据包，内容另含处置轨迹、判据链与触发它的推理明细。

> 权限：查看总览、导出、下载 = 项目成员；留档 = 项目负责人、编辑者。
