> 全链路：逐行推理 → 报错回流 → 阈值告警 → 人工审核 → 自动重训 → 换模上线

## 方案 A：闭环自动化（本页）

### A1 新建闭环任务（配置弹窗）

列表右上「**新建闭环**」→ 弹窗按下表填写 →「创建闭环」：

| 配置项 | 建议值 | 说明 |
|---|---|---|
| 闭环名称 | 方案A演示闭环 | 同名自动改为 ××-2 |
| 推理部署 | 自动化测试 | 逐行预测走它的真实模型 |
| 报错类别 | 1 | 预测=1 判定为报错行 |
| 告警阈值 | 2 | 每 2 行报错触发一次告警 |
| 人工审核 | 开 | 自动创建标注任务并分配 jing |
| 自动重训 | 开 | 报错积累 3 行触发建模 |
| 重训数据集 | labeled_fea.csv + 任务名-报错数据（多选） | 合并训练；报错数据自动用推理结果打标签 |
| 重训目标列 | fault | 分类目标 |

### A2 启动闭环（逐行真实推理）

1. 点行进入**任务详情页** →「上传 CSV」→ 选 `labeled_features_demo.csv`（46 行）；
2. 「**启动闭环**」→ 逐行真实推理：
   - 报错行标红「已回流」，自动写入任务专属报错数据文件；
   - 告警横幅 + 站内通知；人工审核任务自动创建（jing 处理）；
   - 报错积累 3 行 → 自动触发建模（约 90 秒）→ **自动换模**。

### A3 六个环节在哪看

| 环节 | 详情页看 | 事后查 |
|---|---|---|
| 逐行预测 | 行卡片 + 已推理计数 | 模型库 → 部署监控 |
| 错误回流 | 红色「已回流」 | 数据管理 → 报错数据行数 |
| 阈值告警 | 告警横幅 | 右上角铃铛 |
| 人工审核 | 事件流「审核任务已创建」 | 数据标注 → jing 门户处理 |
| 自动重训 | 事件流「已触发 → 完成」 | 自动建模页任务 |
| 模型替换 | 金色「推理模型已替换」 | 模型库 → 部署版本（可回退） |

### A4 重置

详情页「**重置闭环**」：清空计数/事件（配置与报错数据文件保留）。

## 方案 B：应用编排 → API 市场

### B1 搭建服务图（应用编排 → 新建编排 → 画布拖拽）

| 算子 | 作用 | 参数（全部下拉选择） |
|---|---|---|
| API 输入 | 接收逐行调用 | 无 |
| 加载模型制品 | 绑定已训练模型 | 模型制品下拉选 joblib |
| 应用模型 | 推理 | 模型口接加载模型制品 |
| 条件分支 | 报错判断 | 判断列 prediction == 1 |
| 追加报错数据集 | 报错行回流 | 数据集下拉选报错数据 |
| 通知管理员 | 站内告警 | 标题 / 内容 / 级别 |
| 重训阈值判断 | 积累触发重训换模 | 数据集下拉 ×2、目标列 fault、阈值 3、换模部署下拉 |

连线：API 输入 → 应用模型（data）；加载模型制品 → 应用模型（model）；应用模型 → 条件分支；**true** → 回流 → 告警 → 阈值判断；false 为正常出口。

### B2 两步发布

画布顶部「**发布**」（版本快照 v1）→「**发布为 API**」→ 上线市场。

### B3 市场调用（逐行真实推理）

API 市场 →「方案B全闭环服务」→ 详情 → 测试 → 粘贴单行 JSON → 发送。

- 报错行回流同一报错数据集 + 站内告警；
- 报错积累达阈值 → 当次调用触发自动建模（`triggered: true`）；
- 建模完成后**下一次调用自动换模**（调用时闭环设计）。
