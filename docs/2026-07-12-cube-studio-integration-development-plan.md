# 汽车焊接工业 AI 平台开发计划

> 日期：2026-07-12
> 基线：现有 React + FastAPI + SQLite + 单机 DAG 执行平台
> 目标：吸收 Cube Studio 的 MLOps、云原生算力、模型服务和大模型能力，同时保留焊接机理模型与工业场景优势

## 1. 结论摘要

当前项目已具备可视化工作流、79 个算子、基础训练、模型库、知识库、标注、监控和智能体页面/API，可视为“单机版工业 AI 工作流 MVP”。

完整实现 Cube Studio 级别能力，不是页面扩展，而是从单机应用升级为云原生、多租户、可调度、可观测的企业级 MLOps 平台。建议分三档建设：

| 建设目标 | 范围 | 日历周期 |
|---|---|---:|
| A. 稳定可交付版 | 稳定现有工作流、数据、训练、模型、知识库、测试 | 1 个月 |
| B. 企业 MLOps 核心版 | A + 任务调度、实验、模型版本、推理服务、监控、PostgreSQL/MinIO | 累计 2-3 个月 |
| C. Cube Studio 对标版 | B + Kubernetes、多集群、Notebook、镜像、异构算力、计费、AIHub、大模型 | 累计 5 个月 |

目标周期调整为：稳定可交付版 1 个月、企业 MLOps 核心版累计 2-3 个月、全部功能累计 5 个月。开发过程中需要提前冻结需求、架构和模块接口，并采用并行实施方式。

## 2. 计划口径

时间计划包含需求澄清、设计、开发、代码审查、自动化测试、联调、部署文档和缺陷修复，不包含硬件采购、第三方商业授权和长期运维值守。

估算假设：

- 现有代码可继续复用，但需偿还测试隔离、乱码、临时脚本、SQLite、本地文件路径和进程内执行等技术债。
- 第一阶段不兼容 Cube Studio 原数据库和页面，只对齐业务能力。
- 生产环境采用 PostgreSQL、Redis、MinIO；云原生阶段采用 Kubernetes。
- 异构算力首期支持 NVIDIA GPU，NPU/DCU 在后续适配。
- 每周完成代码合并、测试、演示验证和周交付物归档。
- 开发周期以需求和接口按期冻结为前提。

## 4. 目标架构

平台采用“双执行后端”设计：

1. Local Executor：保留当前轻量单机模式，用于开发、演示和小规模工厂部署。
2. Kubernetes Executor：将训练、数据处理和推理任务提交为 Pod/Job，用于企业生产环境。

核心组件：

| 层次 | 建议组件 |
|---|---|
| Web | React、TypeScript、Ant Design、ReactFlow、ECharts |
| API | FastAPI、OpenAPI、WebSocket/SSE |
| 元数据库 | PostgreSQL + Alembic |
| 队列与状态 | Redis + Celery，后续可替换为 Argo/自研控制器 |
| 对象存储 | MinIO/S3，保存数据集、模型、日志和结果 |
| Pipeline | 工作流定义服务、调度器、Local/K8s Executor、运行状态机 |
| 实验与模型 | MLflow 或兼容接口，自研业务管理层 |
| 推理服务 | FastAPI/KServe，支持版本、发布、回滚和指标 |
| 监控 | Prometheus、Grafana、Loki，OpenTelemetry 可选 |
| 身份权限 | JWT + RBAC，企业版对接 OIDC/LDAP |

## 5. 分阶段实施计划

## 阶段 0：基线治理与需求冻结

周期：第 1 周。

工作项：

- 盘点所有页面、API、模型、算子和测试，建立唯一功能台账。
- 清理临时脚本、重复数据库、测试数据和生成文件，制定目录规范。
- 定义“生产可用、功能可用、原型、未实现”四级成熟度。
- 修复当前前端构建、i18n、工作流运行和测试环境问题。
- 建立开发、测试、预发布三套配置和环境变量规范。
- 固化 API 错误码、日志格式、对象 ID、时间和状态枚举。

验收标准：

- 前后端可从干净环境一键构建和启动。
- 后端回归测试、前端单元测试和核心 E2E 全部通过。
- 功能台账与代码路由、API、数据模型一一对应。
- 不再依赖仓库内手工修改的 SQLite 数据库。

## 阶段 1：稳定版工业工作流平台

周期：第 2-4 周。阶段 0 与阶段 1 累计 1 个月完成稳定可交付版。

### 1.1 工作流与执行可靠性

- 工作流草稿、发布版本、复制、导入导出和回滚。
- 节点输入输出类型校验、参数校验、运行前静态检查。
- 运行状态机：pending/running/succeeded/failed/cancelled/timeout。
- 节点级重试、超时、取消、错误详情和日志查看。
- 运行记录、结果制品、工作流快照和可重复运行。
- 大数据预览分页和结果下载，避免浏览器传输完整数据。

### 1.2 数据与制品管理

- 数据集 CRUD、版本、元数据、Schema、预览和下载。
- 文件统一迁移至 MinIO/S3，不在数据库保存本地绝对路径。
- 数据集与工作流运行、模型、标注任务建立关联。
- 支持 CSV、Excel、JSON、Parquet、图片目录。
- 数据生命周期、软删除和垃圾制品清理。

### 1.3 算子体系工程化

- 建立严格的端口类型和参数 Schema。
- 79 个算子统一异常、预览、日志和序列化协议。
- 修复 DataFrame/list/dict/bytes 类型边界问题。
- 增加 LightGBM、PCA、LDA、GBDT、CatBoost、时间序列基础算法。
- 自定义 Python 算子安全执行策略和权限限制。
- 算子版本、弃用、兼容性和测试样例。

### 1.4 工业场景闭环

- 焊接质量预测、参数推荐、异常检测和机理融合四套可交付模板。
- 数据字段映射、工艺参数单位和材料牌号字典。
- 模型评估报告、误判分析、特征重要性和工艺建议。
- 模板向导、示例数据、演示脚本和用户操作手册。

阶段验收：一个新用户可以上传焊接数据，使用模板完成训练、评估、模型保存和结果导出，全流程不需要修改代码。

## 阶段 2：企业 MLOps 核心

周期：第 5-12 周。项目启动后累计 2-3 个月完成企业 MLOps 核心版。

### 2.1 平台基础设施

- SQLite 迁移 PostgreSQL，建立完整 Alembic 迁移链。
- Redis/Celery 异步执行，API 进程不直接承担长任务。
- MinIO 对象存储、统一制品 URI 和下载授权。
- 服务健康检查、结构化日志、配置中心和密钥管理。
- CI/CD：静态检查、测试、镜像构建、安全扫描和部署。

### 2.2 实验与训练管理

- 实验、Run、参数、指标、标签、日志和制品管理。
- 训练检查点、恢复、早停、重复实验和对比页面。
- AutoML 任务、搜索空间、并行 Trial、排名和最佳模型。
- TensorBoard 集成和训练曲线实时展示。
- 训练数据、代码版本、环境和模型可追溯。

### 2.3 Pipeline 调度

- Cron 定时调度、手工补录、依赖、并发限制、超时和重试。
- Pipeline 参数、全局变量、密钥、输入输出映射。
- 运行暂停、恢复、从失败节点继续和实例保留策略。
- 调度日历、实例列表、批量操作和运行告警。

### 2.4 模型注册与推理服务

- 模型注册、版本、阶段、指标、审批和模型卡。
- sklearn/XGBoost/PyTorch/ONNX 基础推理镜像。
- 推理服务创建、启动、停止、在线测试和健康检查。
- 多版本发布、滚动升级、回滚、流量比例和访问密钥。
- QPS、延迟、失败率、CPU/内存/GPU 指标。

### 2.5 权限、审计与通知

- 用户、项目组、项目角色、资源角色和接口权限。
- OIDC/LDAP 接入预留，首期完成一种企业 SSO。
- 删除、发布、权限变更、模型上线等操作审计。
- 邮件、企业微信、钉钉或飞书至少接入一种通知渠道。

阶段验收：训练任务与 API 服务均在后台可靠运行，用户可追踪数据、实验、模型和服务的完整链路，平台能够用于小规模生产。

## 阶段 3：云原生算力与在线开发

周期：第 13-16 周。

### 3.1 Kubernetes 执行器

- 集群注册、命名空间、资源组和节点管理。
- 将 Pipeline 节点提交为 Kubernetes Job/Pod。
- Pod 日志、事件、状态同步、取消和垃圾回收。
- CPU、内存、GPU 请求与限制，节点选择和亲和性。
- 镜像拉取密钥、环境变量、ConfigMap、Secret 和卷挂载。

### 3.2 Notebook 与镜像

- JupyterLab 和 VS Code 实例管理。
- CPU/GPU 规格、续期、停止、自动清理和访问代理。
- Notebook 镜像目录、自定义镜像和保存环境。
- 在线镜像构建、构建日志和镜像仓库凭据。
- Git、SSH Remote、TensorBoard 接入。

### 3.3 多集群与异构算力

- 多集群注册、心跳、资源发现和任务路由。
- NVIDIA GPU 独占/共享；vGPU 依据基础设施选型适配。
- 边缘集群与指定节点调度。
- NPU/DCU 等国产算力每一种单独作为适配项目评估。
- RDMA、卡型和驱动版本作为可选高级能力。

### 3.4 配额、存储和成本

- 项目、用户、任务三级配额。
- 开发、训练、推理资源分类统计。
- NFS、CephFS、S3/MinIO 挂载管理。
- 资源使用报表、成本估算和预算告警。
- 真正的租赁、计费与账单属于独立商业子项目，不纳入首期。

阶段验收：用户可选择资源规格启动 Notebook 或 Pipeline；任务在 Kubernetes 中隔离执行；管理员能查看集群、节点、Pod 和 GPU 使用情况。

## 阶段 4：数据标注、AIHub 与大模型

周期：第 17-20 周。项目启动后累计 5 个月完成全部规划功能。

### 4.1 数据平台与标注

- SQL Lab 和数据库连接管理。
- 表格数据探索、质量分析、统计报告和数据血缘基础版。
- 对接 Label Studio，支持图像、文本、音频和时序数据。
- 标注任务分配、草稿、审核、质量评分和导入导出。
- 标注结果一键转数据集并触发训练 Pipeline。

### 4.2 RAG 与智能体生产化

- PDF/Word/Markdown/网页解析、切片策略和 Embedding 服务。
- 多路召回、重排、引用、检索评估和权限过滤。
- 智能体工具注册、任务状态、重试、人工审核和执行审计。
- 焊接工艺知识库、故障诊断助手和参数推荐智能体。

### 4.3 LLM 网关与微调

- OpenAI 兼容网关、模型路由、密钥、配额和限速。
- QPS/TPS、Token、TTFT、错误率和调用成本监控。
- vLLM 推理服务接入。
- LoRA/SFT 任务模板、训练数据管理和模型评估。
- 量化、剪枝和多机多卡训练放在增强版本。

### 4.4 AIHub 与应用市场

- 算子、模型、Pipeline 和应用统一资产目录。
- 资产版本、标签、介绍、示例、权限和发布审批。
- 一键转 Notebook、一键转 Pipeline、一键部署服务。
- 工业应用模板：焊点质量、缺陷检测、参数推荐、知识助手。

阶段验收：标注、训练、模型注册和部署形成闭环；用户可通过统一网关调用模型；焊接知识助手具备来源引用和权限控制。

## 8. 关键依赖关系

1. 数据库迁移、对象存储和异步任务必须早于实验管理、模型版本和推理服务。
2. Pipeline 状态机必须早于定时调度、恢复、Kubernetes 执行器。
3. 模型制品规范必须早于模型注册、服务发布、AIHub。
4. RBAC 和项目组模型必须早于多集群、Notebook、标注和知识库生产化。
5. Kubernetes 执行器必须早于多集群、异构算力和分布式训练。
6. 监控指标规范必须与训练和推理服务同步设计，不能在最后补做。

## 9. 质量与验收策略

每个阶段必须具备：

- 单元测试：核心业务逻辑覆盖率不低于 80%。
- API 集成测试：所有写接口覆盖成功、权限、参数错误和不存在资源。
- E2E：登录、数据上传、工作流编辑、运行、模型注册、部署主链路。
- 性能：工作流运行、文件上传、日志查询和推理接口有明确基线。
- 安全：依赖扫描、镜像扫描、弱密码、越权、文件路径和代码执行检查。
- 可观测：请求 ID、任务 ID、结构化日志、指标和告警。
- 文档：部署、升级、备份恢复、管理员和用户手册。

## 10. 主要风险

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 当前页面/API 数量多但成熟度不一致 | 估算偏差和返工 | 阶段 0 建立真实功能台账和验收用例 |
| SQLite 与本地文件路径耦合 | 无法横向扩展 | 阶段 2 前完成 PostgreSQL/MinIO 迁移 |
| 进程内 DAG 执行 | 服务重启丢任务 | 引入持久状态机和异步队列 |
| 一次性引入 Kubernetes | 复杂度陡增 | 保留 Local Executor，分阶段增加 K8s Executor |
| 自定义 Python 算子 | 安全风险 | 容器隔离、权限、资源限制和禁用危险能力 |
| 国产算力适配范围过大 | 工期失控 | 每种硬件单独立项，以 NVIDIA 为首期基线 |
| “对标全部功能”持续膨胀 | 无法验收 | 每阶段冻结范围，新增需求进入后续版本 |
| 测试和平台工程投入不足 | 生产质量不可控 | 将自动化测试、发布和可观测性列为阶段验收项 |

## 11. 建议的立项范围

推荐首个正式项目范围为“企业 MLOps 核心版”，累计周期 2-3 个月，交付以下能力：

- 稳定的工业工作流、数据和算子平台。
- PostgreSQL、Redis、MinIO 和标准 CI/CD。
- 实验、训练、AutoML、模型注册和版本管理。
- Pipeline 定时、重试、恢复和运行监控。
- 基础推理服务、发布、回滚、在线测试和指标。
- 项目级 RBAC、审计与通知。
- 四套汽车焊接场景模板和完整用户文档。

第 3 至第 5 个月继续完成 Kubernetes、多集群、Notebook、异构算力、数据标注、AIHub 和大模型能力。五个月总周期要求各子系统在统一架构和接口冻结后并行开发，禁止在开发期持续扩大功能范围。
