# 点焊质量感知与数据标注设计

**日期：** 2026-07-30
**状态：** 已获用户确认，待评审规格后实施
**范围来源：** `点焊质量感知算法报告.docx`

## 1. 目标与边界

在智擎平台内实现报告中的完整、可追溯点焊质量感知流程：

1. 用户上传报告同结构的 CSV/XLSX 数据集。
2. 解码四路 Base64 波形，提取 25 个表格特征和 48 个波形特征，形成 73 维特征。
3. 执行 10 组、7 类候选模型的 AutoML 选型。
4. 按最佳模型特征重要性加权执行 KMeans、K=2..8 轮廓系数搜索和 PCA 可视化。
5. 用聚类和工艺规则产生可审计的弱监督标签。
6. 在独立“数据标注”页面中人工复核、修正和审核标签。
7. 使用确认标签训练 LightGBM 与三组 MLP 对照模型，登记模型与制品血缘。
8. 批量推理并输出四级预警、可下载结果和质量感知报告。

本交付提前实施当前计划中“数据探索与标注”的相关范围，但只覆盖点焊质量数据，不建设通用 SQL Lab、多模态标注或外部数据库连接。

不在本范围内：

- 不连接报告中列出的 PostgreSQL 地址，不索取或伪造任何凭据。
- 不承诺复现报告中的 1875 条样本、AUC、缺陷数量或比例；这些结果只能由用户上传的真实数据生成。
- 不替换既有 `/annotations` 图片标注功能，也不让图片标注 API 承担波形质量数据。
- 不接受用户上传 `pickle`、`joblib` 或任意模型文件进行执行。

## 4. 输入数据合同

### 4.1 数据集制品

文件继续通过既有项目级数据集上传接口保存为 Artifact。质量运行只接受项目内、当前用户有读取权限的 `dataset` Artifact ID；不接受本地绝对路径、跨项目制品或 URL。

支持 CSV、XLS 和 XLSX。创建质量运行前，用户完成字段映射并获得验证结果；映射和输入制品 SHA-256 会冻结在该运行中。

### 4.2 必填映射

默认映射报告中的字段名，并允许用户映射同义列名。必填项为四路波形和 14 个原始表格字段：

- 波形：`cvei`（电流）、`cvev`（电压）、`cver`（电阻）、`cvep`（功率）。
- 工艺字段：`wld1c`、`wld2c`、`tipv1`、`tipv2`、`wres`、`energy`、`wld_spatter_strength`、`wld1_spatter_strength`、`wld2_spatter_strength`、`spatterpos_wld`、`spatterpos_pre`、`spotdiameter`、`spotposition`、`spattercode`。

可选映射包括稳定的业务样本标识和原始目标列。原始目标列存在时可用于报告顺序的初始监督 AutoML；不存在时运行规则优先的弱监督启动路径，运行详情必须明确显示该差异。

### 4.3 验证行为

每个波形必须可严格 Base64 解码为 1740 字节，再按 `numpy.frombuffer(raw, dtype=">i2")` 得到 870 个样本点。缺列、不可解析数值、无效 Base64、错误字节长度或错误采样点数会生成行级错误报告并阻止质量运行；不得静默截断、补零或丢弃样本。

验证阶段还检查：样本标识唯一性（若提供）、映射列是否重复、可用行数、标签类别的最小折数可行性，以及 CSV/XLSX 解析错误。原始数据、验证报告和字段映射均作为可下载制品保存。

## 5. 质量感知运行

### 5.1 不可变运行记录

每次启动创建一个项目级质量运行。运行保存输入 Artifact、输入哈希、字段映射、代码/特征版本、规则集版本、统计阈值、随机种子、阶段状态和所有输出 Artifact ID。历史运行不可覆盖；重新运行创建新记录。

质量运行阶段为：`validating`、`featurizing`、`automl`、`clustering`、`weak_labeling`、`awaiting_review`、`training`、`predicting`、`completed`、`failed`。长时间计算由后台任务执行，页面通过已有任务状态机制查询进度和稳定错误码。

### 5.2 特征工程

实现报告的 `report_v1` 特征模式：

- 14 个原始表格字段和 11 个报告派生表格特征，共 25 维。
- 每路波形提取 `mean`、`std`、`max`、`min`、`pp`、`median`、`rise_time`、`stable_mean`、`stable_std`、`avg_diff`、`max_diff`、`p95_diff`，共 4 x 12 = 48 维。
- 组合为严格排序、名称稳定的 73 维特征模式。训练、聚类和推理都只能使用同一冻结模式。

派生指标使用运行内统计量，包含 `energy_dev`、`diameter_norm`、飞溅总量/不对称度、阶段功率和比值等报告定义。零分母、无穷值和非有限结果均作为验证错误，而非隐式替换值。

特征矩阵、统计阈值、特征字典和数据质量报告保存为生成制品。原始 Base64 波形不会复制到关系数据库。

### 5.3 AutoML

质量配方补齐当前 AutoML 未覆盖的 LightGBM 和 CatBoost 依赖，并固定报告的 10 组候选：LGB_v1/v2、XGB_v1/v2、CAT_v1/v2、GBDT_v1、RF_v1、ET_v1、HGB_v1。候选的参数、随机种子、持续时间、失败原因、逐折得分和排名都保存。

使用三折分层交叉验证。二分类使用 ROC-AUC；多分类使用 OvR macro ROC-AUC；F1 使用 macro 平均。先比较 AUC，再比较 F1，最后按配置序号稳定打破完全相同的并列。类别样本数不足三折时以稳定错误码失败，不降低折数后伪称已复现报告。

若映射原始目标列，AutoML 在聚类前运行。若没有原始目标列，系统先按 `report_v1` 规则生成启动伪标签，再执行 AutoML；该运行记录为 `rule_first`，不声称与报告的监督顺序相同。

缺少必需运行时依赖时，质量配方返回 `QUALITY_AUTOML_DEPENDENCY_UNAVAILABLE`，不会静默跳过 LightGBM 或 CatBoost。

### 5.4 加权聚类与 PCA

从最佳树模型获取 73 维 `feature_importances_`，归一化后以平方根权重缩放标准化特征。对 K=2..8 计算轮廓系数，选择最高分；同分时选择较小 K。运行固定随机种子并保存每个 K 的得分、最终簇、簇画像和二维 PCA 坐标。

KMeans 数字 ID 和按飞溅/能量计算的异常簇画像都作为聚类分析结果保存。报告自动标注的 `report_v2` 规则按工艺要求固定使用原始 `cluster_id = 1`，不再以动态异常簇角色决定标签；固定随机种子和保存的 cluster ID 保证同一输入可复核该规则。

### 5.5 弱监督规则

内置不可变 `report_v2` 规则集；历史 `report_v1` 运行保持原始结果。默认规则依报告表格顺序决定主标签：

1. 强飞溅：`wld_spatter_strength >= 3`
2. 弱飞溅：`wld_spatter_strength == 2`
3. 焊点过小/虚焊：`0 < spotdiameter < 2`
4. 焊点过大/烧穿：`spotdiameter > 80`
5. 能量异常：`abs(energy_dev) > 2.5`，其中 `energy_dev` 是运行内能量 z-score，等价于偏离均值超过 `2.5σ`
6. 电流波形异常：`current_max_diff > P95`
7. 功率波动异常：`power_std > P95`
8. 飞溅倾向簇：`cluster_id == 1` 且 `wld_spatter_strength >= 2`
9. 正常：以上均未命中

`spotdiameter=0` 表示未测量，永不命中虚焊规则。每个样本保存全部命中规则、主标签、规则集版本、统计阈值和簇结果；主标签按规则顺序生成，但不丢失后续规则命中。人工修订只改变人工标签状态，不改写自动规则结果。

## 6. 标注、审核与权限

### 6.1 标签状态和版本

样本状态依次为 `pending_review`、`in_review`、`submitted`、`approved`、`returned`。每次创建、修改、提交、通过或退回都会新增标签修订，记录操作人、时间、人工主标签、说明、审核意见和此前版本。任何修订不覆盖原始数据、自动标签、规则命中或先前审核证据。

只有 `approved` 标签组成可训练快照。训练请求必须保存快照 ID、包含样本数、类别分布和质量运行 ID；后续人工改标不会修改已开始或已完成训练的标签集。

### 6.2 项目授权

所有质量运行、样本、波形、标签、报告、训练和预测 API 均先核验项目成员权限，再按资源的项目 ID 查询：

- owner/editor：上传、字段映射、启动/重试运行、管理规则版本、审核标签、开始训练、模型部署和导出。
- operator：读取项目数据、领取样本、创建或修改人工标签、提交审核；不能改规则、通过审核、训练或部署。
- viewer：只读已授权项目的运行、样本和预警，不能读取他项目数据或写入任何状态。

写操作走既有项目审计边界，审计资源 ID 绑定实际质量运行、样本或规则版本。不得用仅 owner ID 的旧查询替代项目角色解析。

## 7. 训练、模型与预警

### 7.1 二阶段训练

确认标签达到五折分层要求后，执行报告的四组对比：AutoML 最佳 LightGBM、MLP_128-64-32、MLP_256-128-64、仅表格特征的 MLP_128-64-32。多分类评估保存五折 AUC、F1、准确率、混淆矩阵和类别分布。

若确认标签不足五折，训练以 `QUALITY_LABELS_INSUFFICIENT_FOR_5_FOLD` 失败并指出各类别数量；不得在后台缩减到无记录的折数。模型包只由平台创建，包含预处理器、冻结特征模式、标签快照和模型元数据，并通过现有 Artifact/模型库血缘登记。

### 7.2 推理与预警

推理严格校验输入特征模式和预处理版本。全量结果保存每行的主类别、类别概率、缺陷概率、预警级别、质量运行和模型版本。四级预警固定为：

| 级别 | 缺陷概率 |
| --- | --- |
| 严重 | `>= 0.8` |
| 警告 | `>= 0.6` 且 `< 0.8` |
| 提示 | `>= 0.3` 且 `< 0.6` |
| 无 | `< 0.3` |

每条预警可进入数据标注页对应样本。批量结果、预警分布和质量感知报告保存在项目 Artifact 中，可经已有授权下载流导出。

### 7.3 报告制品

每个完成运行生成与报告对应的可下载结果：总览、AutoML 选型、深度学习对比、缺陷标签、聚类画像、特征重要性、推理结果、多分类评估。图表在页面显示，数据与工作簿由生成制品保存；不将临时本地路径或外部数据库地址持久化。

## 8. 数据模型与 API 边界

新增项目级持久模型并通过单一 Alembic 迁移接入：

- `spot_weld_quality_runs`：不可变运行配置、阶段状态、输入/输出 Artifact、统计阈值、模型和错误详情。
- `spot_weld_quality_samples`：运行内样本索引、来源行标识、簇、自动标签、规则命中、预测与审核状态；波形和完整特征由关联生成制品按行取得。
- `spot_weld_label_rule_sets`：项目规则集和不可变版本内容。
- `spot_weld_label_revisions`：人工标签和审核的 append-only 历史。
- `spot_weld_label_snapshots`：训练时锁定的已确认标签集合。

新增 `/api/projects/{project_id}/spot-weld/...` 路由组，涵盖字段验证、创建/查询质量运行、分页样本队列、单样本波形与详情、标签修订、审核、规则集版本、训练、推理和生成制品列表。通用 `/api/labeling` 保持无状态工具接口，不被新的持久化流程复用。

## 9. 错误处理和可观测性

质量流程暴露稳定、非敏感错误码，包括：`QUALITY_REQUIRED_COLUMN_MISSING`、`QUALITY_WAVEFORM_INVALID_BASE64`、`QUALITY_WAVEFORM_LENGTH_INVALID`、`QUALITY_FEATURE_NONFINITE`、`QUALITY_LABELS_INSUFFICIENT_FOR_3_FOLD`、`QUALITY_LABELS_INSUFFICIENT_FOR_5_FOLD`、`QUALITY_AUTOML_DEPENDENCY_UNAVAILABLE` 和 `QUALITY_RUN_NOT_READY`。

运行失败保存阶段、错误码、可展示说明和不含样本敏感值的诊断信息。候选模型失败保存候选级状态而不是吞掉异常；全部候选失败才使 AutoML 阶段失败。每个后台阶段产生结构化日志、审计事件和制品引用，便于从模型、预警或人工标签回溯到输入文件。

## 10. 验收与测试

实现前先新增失败测试，测试文件登记到后端 `week_manifest.py` 或前端 `weekAcceptance.test.ts`。最低验收集包括：

1. 严格大端序 `>i2` 解码、1740 字节/870 点、48+25=73 维和无穷值拒绝。
2. CSV/XLSX 字段映射、项目制品边界、无效 Base64、错误长度和行级错误报告。
3. 10 个 AutoML 配置、三折 AUC/F1 排序、缺依赖错误和候选失败记录。
4. 特征重要性加权、K=2..8 搜索、确定性并列规则、PCA 和异常簇角色。
5. `spotdiameter=0`、全部规则命中、主标签优先级和规则版本冻结。
6. 标签修订 append-only、审核状态机、标签快照不可变和确认标签训练边界。
7. owner/editor/operator/viewer 的跨项目读取、写入和审核拒绝回归。
8. 模型库血缘、特征模式拒绝、四级预警阈值和结果制品导出。
9. 独立导航“数据标注”、旧图片标注可访问、四波形 UI、人工复核动作和窄屏无重叠前端回归。
10. Alembic 迁移、后端聚焦/全量套件、前端 Vitest、TypeScript/Vite 构建；本地结果与远程 CI 结果分别记录。

## 11. 实施顺序

1. 先建立数据模型、迁移、严格特征/波形服务和后端测试。
2. 将质量数据集入口接入数据管理，并保存验证与运行制品。
3. 实现质量 AutoML、加权聚类、规则弱标注、报告制品和后台任务。
4. 新增独立数据标注导航、页面和审核 API，再扩展模型库与预警视图。
5. 实现确认标签训练、推理、预警和全链路回归。

每一步保持通用数据集、通用标注、既有训练和模型库 API 向后兼容。实现完成后更新 `DEVELOPMENT_PLAN.md`、项目经验文档、测试清单和遗留风险记录。
