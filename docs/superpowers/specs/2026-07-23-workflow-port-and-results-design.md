# 工作流端口与结果交互修复设计

## 范围

修复 `docs/bug列表.txt` 中六项工作流问题：端点唯一连接、处理/融合原始数据输出、端点预览、失败详情、评估算子执行、可视化结果展示。

## 端口与连线契约

- 每个逻辑输入端口和逻辑输出端口最多一条连线。
- 新连线使用的源端口或目标端口已有连线时，删除冲突旧边后新增新边。
- 端口 ID 使用稳定端口名；历史 `__slot_N` ID 在读取、保存和连线解析时归一化为逻辑端口名。
- 前端不再为同一逻辑端口创建动态 slot；端口数量只由算子元数据决定。

## 原始数据输出

- `processing` 类算子增加 `raw_data` 输出端口，值为其 `data` 输入的未处理副本。
- `blending` 类算子为每个输入端口增加 `raw_<input_port>` 输出端口，值为对应输入的未处理副本。
- 通过注册表/执行契约统一补充端口与输出值，避免逐个算子复制实现。
- 补充后的输出仍必须通过 `OperatorResult` 声明端口校验。

## 画布交互

- 端点悬停显示端口类型、数据格式、数据摘要和样例预览。
- 点击端点关闭当前预览；离开后再次悬停可重新显示。
- 失败节点状态标签可点击，打开错误详情弹窗，显示错误码、错误消息、节点 ID 和尝试次数。
- 已完成且类别为 `visualization` 的节点点击后打开独立结果面板；面板显示该节点输出、指标、日志及可渲染图表/表格/JSON 摘要。

## 评估算子

- 审计所有 `evaluation` 类算子的注册、`inputs`、`outputs`、参数定义和 `execute(context, inputs, params)` 签名。
- 修复不符合 `OperatorResult` 契约、未注册或输出缺失的实现。
- 为每个评估算子建立最小可运行执行回归。

## 测试与验收

- 前端：同逻辑输入/输出端口新边替换旧边；历史 slot ID 归一化；端点预览与点击隐藏；失败标签错误弹窗；可视化节点结果面板。
- 后端：处理类原始输出、融合类每输入原始输出、全部评估算子注册/可执行/返回声明输出。
- 集成：工作流执行后 WebSocket 状态携带节点错误与结果，画布显示对应详情。
- 验收：相关前后端测试、前端生产构建、`git diff --check`；浏览器验证端点、失败详情和结果面板。

## 非目标

- 不改变工作流权限、发布版本、调度、DataBus 存储格式或既有非处理/融合算子业务语义。
- 不为评估、可视化以外类别增加结果面板入口。
