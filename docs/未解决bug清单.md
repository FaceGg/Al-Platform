### 已解决缺陷

#### BUG-PROJ-001 | 已解决 | 删除包含实验记录的项目返回 500

- 来源：本地 `DELETE /api/projects/{project_id}` 运行日志。
- 现象：项目存在 Experiment 时，删除接口在提交事务中将 `experiments.project_id` 更新为 `NULL`，触发非空约束并返回 500。
- 已确认根因：`Experiment.project` 使用没有删除级联的 ORM backref；虽然数据库外键声明 `ON DELETE CASCADE`，SQLAlchemy 仍先尝试解除关系。
- 解决情况：单删和批删均在删除 Project 前显式删除该项目的 Experiment；原有 TrainingJob、Dataset 和 OrchestrationApp 清理顺序保持不变。
- 验证：单删与批删回归均先稳定返回 500，再修复为成功并确认 Experiment 不存在；`tests.test_api_projects` 14/14、项目授权 15/15、实验 API 9/9、后端隔离全量 84/84 通过。

#### BUG-WF-001 | 已解决 | 历史索引端口连线不会被新连线替换

- 来源：`docs/bug列表.txt` 第 1 项“每个端点只能有一条连线”。
- 现象：已保存的历史边使用 `out-0` 或 `in-0`，当前节点使用命名端口（如 `data`、`input`）。在同一逻辑端点创建新边时，旧边不会被删除，端点可保留两条边。
- 已确认根因：`normalizeWorkflowHandle()` 仅移除 `__slot_N` 后缀；`hydrateWorkflowEdges()` 保留 `out-N`/`in-N`；`onConnect()` 因此把历史索引端口与当前命名端口当成不同端点比较。
- 证据：`ml-platform/frontend/src/stores/workflowStore.ts:55`、`ml-platform/frontend/src/stores/workflowStore.ts:137`、`ml-platform/frontend/src/pages/WorkspacePage.tsx:26`、`ml-platform/frontend/src/pages/WorkspacePage.tsx:35`。
- 解决情况：`hydrateWorkflowEdges()` 接收已解析节点，将源 `out-N` 映射到输出端口、目标 `in-N` 映射到输入端口，再使用原有去重规则；未知索引保持原值。初次加载和运行前重载均传入节点元数据。
- 验证：新增历史索引边与命名边冲突回归，旧实现按预期保留两条边；修复后 `WorkspacePage.test.ts` 11/11 通过，前端全量 31 文件、109 用例通过，生产构建通过。

#### BUG-API-001 | 已解决 | 非法 AgentTask UUID 可触发 500

- 来源：全项目测试审计记录中的潜在源码问题，已在当前代码复核。
- 现象：向使用 `_task_for_user()` 的 AgentTask 路由传入非 UUID 的 `task_id`，直接调用 `uuid.UUID()` 会抛出 `ValueError`，而不是返回客户端可处理的 404 或 422。
- 已确认根因：`ml-platform/backend/app/api/orchestration.py:37` 没有捕获 UUID 解析异常；同文件的 `_agent_for_user()` 已有异常处理，可作为一致性参考。
- 解决情况：`_task_for_user()` 在 ORM 查询前捕获 `TypeError`、`ValueError` 和 `AttributeError`，与 `_agent_for_user()` 保持一致，返回 `None` 以复用既有 404 和资源隐藏语义。
- 验证：新增非法 UUID 消息路由回归，旧实现返回 500；修复后聚焦回归 1/1、`tests.test_agents` 9/9、后端完整套件 84/84 通过。
